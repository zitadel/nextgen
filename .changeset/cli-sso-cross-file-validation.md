"@zitadel/cli": minor
"@zitadel/config": minor
---

`zitadel plan` and `zitadel apply` now check the SSO configuration across files before anything is sent. A flow step that offers a provider its user schema does not list, or when SSO is off; a schema that lists a provider with no connection file; a step that offers providers but does not route every outcome; a claim mapping that fills nothing the schema defines; and a mapping or `verified_claims` key that names a property no schema has, or a `verified_claims` key with no mapping, now stop with one error that names the file, the steps and the name at fault, and what to change. A connection that cannot create users needs only `sso_authenticated` routed and no claim mapping. `@zitadel/config/validate` is now one validation library: `validateFlowDefinition` for a single flow and its schema, and the new `validateProject` for the whole working tree, with every rule named once in a typed registry.

The connection files get the same treatment. Two files with the same slug stop `plan` and `apply`. A `client_id` or `client_secret` that names a project variable which does not exist now fails with `E_CREDENTIAL_MISSING`, naming the variable and the file. Editing the `slug`, `protocol`, `oidc.issuer`, the OAuth2 endpoints or `subject_claim` of a connection that was already applied is refused with the field and file named. A connection file removed after it was applied is reported by `plan` (in the text and in `--json` warnings) and `apply` as not supported yet, and no deletion is sent. A renamed connection file is tracked under its new name.

A removed connection file is now reported apart from the changes: `plan --json` and `apply --json` carry an `unsupported_deletions` count and list, the headline no longer says "no changes", and `apply` no longer says everything is in sync. A renamed connection file is planned and reported as a move (`move` in `changes`, with `moved_from`). The cross-file check reports only the files a plan touches and the files they reference, so an unrelated connection edit is not stopped by an older mistake in another flow. A client secret must be a secret variable and a client id a plain one, and `plan` stops when the project's variables or an edited connection's stored copy cannot be read, instead of skipping the checks; none of these checks is turned off by `ZITADEL_SKIP_FLOW_VALIDATION`. A `verified_claims` entry always needs its `claim_mapping` row, a dotted mapping name names no property, and a `user_already_exists` route with an action is not a route for an SSO collision. `FlowValidationRuleId` is now `FlowRuleId`; the old name stays as a deprecated alias.
