Add SvelteKit, TanStack Start, SolidStart and Qwik City meta-framework SDKs, mirroring sdk-next and sdk-nuxt. Each ships a server integration that proxies `/__nextgen/*` to the auth backend (attaching the project service-key as the bearer), verifies the session JWT via JWKS with the Web Crypto API, and redirects unauthenticated requests on protected routes, plus a `getAuth` helper. These SDKs are server-only; the login/logout widgets are rendered with the matching framework component SDK (`@zitadel/sdk-svelte`, `@zitadel/sdk-solid`, `@zitadel/sdk-qwik`). The server glue uses each framework's native primitive: a SvelteKit `handle` hook (`createNextgenHandle`), a SolidStart `onRequest` middleware (`createNextgenMiddleware`), a Qwik City `RequestHandler` (`createNextgenOnRequest`), and a TanStack Start request middleware (`createNextgenRequestMiddleware`, with the framework-agnostic `handleNextgenRequest` core exported too). All JWT verification and proxy logic is shared from `@zitadel/sdk-core`. sdk-tanstack-start additionally exposes typed React widget wrappers on its `/react` entry like sdk-next, since React needs no compiler.

sdk-qwik-city targets Qwik 2: it peers `@qwik.dev/core` and `@qwik.dev/router` (`^2.0.0-beta.45`), like `@zitadel/sdk-qwik`, whose widgets its pages render. A Qwik 1 City app (`@builder.io/qwik-city`) must migrate to `@qwik.dev/*` first.

The CLI now detects, scaffolds, and integrates all four meta-frameworks end to end. New detectors recognise SvelteKit (`@sveltejs/kit`), SolidStart (`@solidjs/start`), Qwik City on Qwik 2 (`@qwik.dev/router`) and TanStack Start (`@tanstack/react-start`) and run before their base-SPA detectors so a meta-framework app is no longer mistaken for a bare SPA (the React detector now also excludes TanStack Start). Each gains a scaffolder and a patcher that wires the framework-native server entrypoint (`src/hooks.server.ts`; `src/middleware.ts` registered via the `solidStart()` plugin in `vite.config.ts`; `src/routes/plugin@nextgen.ts`; and a `src/start.ts` request middleware respectively), the landing/login/register/profile routes rendering the widgets from the framework component SDK, the public project-id env var, and the matching `@zitadel/sdk-*` dependency.

sdk-tanstack-start's `/react` widgets mount on the client only: the server and hydration render nothing, and the widget mounts right after hydration with every prop in place, so a page never starts with the widget's defaults. `/react` also exports `businessLocales` and the `ZitadelLoginProps`, `ZitadelLogoutProps` and `ZitadelSessionProps` types, like `@zitadel/sdk-react`; `/client` exports `configureZitadel`, `getApi` and `getZitadelConfig`, like the other meta-framework SDKs. The TanStack Start `/profile` route that setup writes guards itself in `beforeLoad` with a server function that returns `getClientAuth(context)`, so the session token stays in its HttpOnly cookie; it sends only a signed-out visitor to `/login`, and shows an error instead when Zitadel is unavailable.
