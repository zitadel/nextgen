"@zitadel/cli": patch

Every command that answers a question now does so in the same words. A list that finds nothing says `No <things> found.` whatever the list is, and counts what it found in the resource's own plural, both derived from the resource rather than written out per command, so `zitadel deployment list` no longer says "No deployments yet" where `zitadel users list` says "No users found" and `zitadel api ls` no longer heads an empty table with nothing under it. `zitadel api ls` is rendered like every other list: the count is its closing line, dim and on its own, instead of a sentence of prose that wrapped under the table. `zitadel deployment get` lays its record out like every other `get` — at the left margin, headed by the deployment's id, with each field named as the wire names it — and hands a pipe the record itself. `zitadel release create` and `zitadel deployment create` each end on one line saying what they did, so the content digest no longer crowds out the sentence and a bulleted origin no longer lands in the middle of it; the digest and the origins are in `--json`, `zitadel release get` and `zitadel deployment get`. `zitadel env` now ends on a line of its own saying which environment, project and server it resolved, where before it ended on nothing. The first release `zitadel setup` creates is now recorded as "Initial deployment from setup" rather than "Initial deployment from zitadel setup", so `release list` reads the way the rest of the CLI does. `--json` is otherwise unchanged throughout.
