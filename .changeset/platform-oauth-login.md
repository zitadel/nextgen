`zitadel login` signs you in to a server as yourself, in the browser: it finds the server's authorization server from the API's protected-resource metadata and signs in with PKCE on a loopback redirect. The tokens are kept in the CLI's user config directory, readable by you alone. `zitadel whoami` shows who the server says you are, and `zitadel logout` revokes the sign-in. `zitadel deployment list` acts as you when no project secret is set. The server offers this behind `platform.oauth.enabled`, which needs `platform.bootstrap_project`. It serves the platform project's OAuth 2.1 authorization server for the CLI and for MCP clients, which register through client ID metadata documents or dynamic registration, and an `/mcp` endpoint with a `whoami` tool. Signing in goes through the console's login page: the authorization endpoint hands the request to it, its `<zitadel-login>` signs you in, asks your consent for a third-party client on a step of its own, and returns you to the client. A browser already signed in to the console is not asked to sign in again. A third-party client asks for consent once, and again only for scopes the user has not agreed to; each consent lasts 90 days at most (`platform.oauth.consent_lifetime`). `GET /users/me/consents` lists the apps a user connected, and `DELETE /users/me/consents/{consent_id}` revokes one with every token it holds. `GET /users/me` and the operations a console session may call also take the access token it issues.
