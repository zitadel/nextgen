**Breaking:** the login widget, the session and logout widgets and every atom attach closed shadow roots in the published package, the npm entries and the standalone file alike. `host.shadowRoot` is now `null`, so `document.querySelector("zitadel-login").shadowRoot`, the same walk through a nested `<zl-field>`, Playwright locators (`getByRole`, `getByLabel`, `locator("zl-field input")`) and any DOM walk that recurses through `el.shadowRoot` find nothing, and an event raised inside reaches the page retargeted to the host with `composedPath()` listing no node inside. Builds that run the source, which is what the component tests and Storybook use, keep the roots open through one constant, `SHADOW_ROOT_MODE`; an app's dev server resolves the published package and gets closed roots like production.

What stays reachable to any script on the page, at any time: the element's public `renderRoot`, `attachInternals().shadowRoot` on the login, session and logout widgets, the part Lit keeps on the element (found by walking its own properties), patched built-ins such as `attachShadow` and `HTMLInputElement.prototype.value`, `getSelection().toString()` after a select-all on a non-password text field, browser extensions, and the native events the browser delivers to a page-level capture listener whatever the root: `keydown` and `keyup` with their `key`, `beforeinput` and `input` with their `data`, `paste` with its clipboard data, and composition events. The values the widget itself puts in its `zl-input` and `zitadel-flow-input` event details are a separate leak, fixed by the secret-leak change. A closed root is a guard against casual reads and not a security boundary; full isolation needs a cross-origin iframe.

To drive the widget, open the roots first: `@zitadel/testing/playwright` now opens them for every page in its `test`, adds `widgetTest` for suites without an instance, and exports `openShadowRoots(page)` for pages created by hand. Any driver that can run a script before the page's own can install the same `attachShadow` override, which only applies to pages loaded after it, so reload a page that was already open; a driver on the DevTools protocol can read the closed roots directly.
