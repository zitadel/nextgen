The login widget, the session and logout widgets and every atom now attach closed shadow roots in the published package, the npm entries and the standalone file alike, so `document.querySelector("zitadel-login").shadowRoot` is `null` and an event raised inside reaches the page retargeted to the host, with `composedPath()` listing no node inside. Builds that run the source, which is what the component tests and Storybook use, keep the roots open through one constant, `SHADOW_ROOT_MODE`; an app's dev server resolves the published package and gets closed roots like production. A closed root is a guard against casual reads and not a security boundary: a script that inspects the element's own properties (Lit keeps a reference to the root there), one that runs before the widget, native key events and browser extensions all get past it, and full isolation needs a cross-origin iframe. Consumers who pierce the widget's shadow roots, with Playwright or a DOM-walking agent, must open them first: `@zitadel/testing/playwright` now opens the roots of every page in its `test`, adds `widgetTest` for suites without an instance, and exports `openShadowRoots(page)` for pages created by hand; a driver on the DevTools protocol can read the closed roots directly.
