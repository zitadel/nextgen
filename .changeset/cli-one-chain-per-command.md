Every command that talks to you now draws one chain from start to finish: a line saying what it is doing, the questions it asks, what it did, and one line saying how it ended. What to do next is one box of steps, laid out the same way in every command, with the commands to run on their own lines. A run that changed nothing, such as a declined confirmation or one with nothing left to do, says what it left in place and the command that moves it on, instead of the reason the envelope carries. Output stays within 80 columns whatever a command reports, a wide table included, while a table printed on its own keeps its columns. A command's own lines stay as it wrote them rather than running together into one paragraph, and only a command you can run is drawn as one — the files `zitadel pull` wrote read as a list of files, and the variables `zitadel env add` asks you to set read as values to copy. `--json` runs are unchanged. `zitadel setup` joins them: its steps sit in the chain, its dependency install is a step like any other, and the report it ends on is the same box whether or not anyone is at a terminal. The chain belongs to the ten commands that walk you through something — `setup`, `deploy`, `pull`, `doctor`, `status`, `env add`, `eject`, `branding eject`, `claim` and `auth-method sso enable`. Every other command looks the same on every run: no chain and no box, a question asked as one plain line with the answer typed on it, and the result at the left margin with one line saying where it ran. `--force` now only removes the question; it no longer changes how the command looks.
