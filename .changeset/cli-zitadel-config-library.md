Every command now reads, checks and writes `.zitadel/` through one configuration library, so they all hold the files to the same rules and refuse with the same errors. `@zitadel/config` adds `referencedClientIdVariable` and `referencedClientSecretVariable`, which read a credential reference as the variable it names.

**Breaking:** `setup` writes the configuration and publishes it in its first deploy instead of creating each resource on its own. When that deploy is refused, `setup` still succeeds, keeps the project and files, and suggests `deploy`. The `auth-method` commands refuse when any file under `.zitadel/` does not parse or fails its contract, even a file the command does not change. `auth-method` results report `notices` instead of `kept` and `untouched`. New `.zitadel/state.json` files have no `resources` section. `setup` and `branding eject` replace an outdated `.zitadel/meta/` schema without `--force`. `doctor`'s schema check validates every file under `.zitadel/`. Deploy's lockout check no longer follows a transition into another flow, and a literal `client_secret` is refused by the `connection/literal-secret` rule. `deploy` also refuses a schema or flow step that lists the same provider twice (`sso/duplicate-provider`), a connection with a field its contract does not know (`sso/unknown-connection-field`), a claim name with surrounding whitespace (`sso/claim-name-whitespace`) and a sign-up through a connection that can create a user without an attribute the schema requires (`sso/collection-misses-required`).
