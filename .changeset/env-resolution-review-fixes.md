Make the environment-resolving commands honest about the environment they were pointed at. `claim --env` now mints and polls the claim challenge for the project the resolved environment names — the one tied to its credential — instead of the fallback `.zitadel/secret` project, records a completed claim only when the local secret is that project's own record so environments are never conflated, and no longer requires `.zitadel/secret` when an env file supplies the project. `status --env` reports the project the user probe actually queried, built from the same resolved environment rather than from `zitadel.json`/`.zitadel/secret`. `zitadel env` fully redacts secret values with a fixed, length-independent mask so a short secret is never shown whole. `zitadel eject` now backs up and removes `.env.development.local` alongside `.env.local`, and setup / `doctor --fix` re-assert `0600` on an existing `.env.development.local` so it can never be left world-readable. `env add` writes the normalized `--app-url` as `ZITADEL_ISSUER` into the generated file and only tells you to copy a secret from that file when one was actually written to it. Setup's SSO recovery command now selects the generated development env file so it cannot send a production token to the local server. A missing required value on an interactive terminal is now prompted for and persisted to `.env.<name>.local`, while non-interactive runs still fail deterministically. `doctor` accepts `--env` / `--env-file` and, when given one, verifies the resolved environment's server is reachable and its project matches.
