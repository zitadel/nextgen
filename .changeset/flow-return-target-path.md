An SSO flow submit checks its `return_target` as a browser reads it, and refuses with `400 req.invalid` any target that a browser or a proxy could take to be another place than the one it names. It must be a printable-ASCII http or https URL with a plain host, an in-range port, no userinfo and no backslash in its authority or path, and its path, however its dot segments (also when written `%2e`) are resolved and its escapes decoded any number of times, must not start with `//`. In the path and fragment, a '%' that starts no escape is stored as `%25` and a character Go would re-encode is stored as its escape, so the stored target keeps the escapes the page sent; the query is stored as sent. A path starting that way is on the request origin, but a proxy that re-bases the callback's redirect onto its own host would read it as another host and send the browser there after sign-in. The sign-in callback checks the stored target again before it redirects to it and answers a 500 error page if it fails.
