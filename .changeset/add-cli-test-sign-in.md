Add `zitadel test sign-in`, which checks that the sign-in providers are set up correctly before anyone signs in. It checks every connection the project has, one block each, and `--provider <slug>` checks just one. It reads the provider's discovery document, checks that it lists the endpoints the runtime needs (authorization, token and, unless claims come from the ID token, userinfo), then the issuer, the scopes and the claims the connection asks for, and asks the provider whether it accepts the client and the callback URI. These checks make plain HTTP requests, need no browser and never need the client secret, which the platform stores write-only. Each prints as it finishes and ends in `pass`, `warn`, `fail` or `skipped`; a check that cannot tell is `skipped`, never a pass, and a failure exits with `E_VALIDATION` and the one thing to do about it. The provider answers are known for Google today; any other provider runs the discovery checks only.

`--live` adds a real sign-in: it opens the login page, waits for you to sign in, and reports from the project's audit events which phase failed and on which side, provider or journey. It is off by default, works against any server the project is on, needs a claimed project (the events of an unclaimed one are hidden) and the files applied, and starts nothing on a dry run. To support it the server's SSO audit events now name the connection and, on failure, the reason and whose side it was, and a new `auth.sso.resolution.failed` event records a sign-in that failed after its exchange: while matching the identity to a user, creating the user, or handing the attempt off. The events never carry authorization codes, tokens, secrets or claim values.
