Apps: one document per app that holds its clients, the APIs it serves and whether clients may register into it. `POST /apps` creates an app or revises it by slug, and `POST /apps/query`, `GET /apps/{id}` and the revision reads return it with each client's `client_id`. A client keeps the `client_id` the server minted or the one its document chose, for life, states its `type`, and takes RFC 7591's `grant_types`; a confidential client without `grant_types` holds only credentials. Credentials are named and written on their own: `POST /apps/{id}/clients/{client}/credentials` adds a generated secret, shown once, an imported secret or hash, a v4 bcrypt hash included, or a public key, for declared and registered apps alike, and a deploy never removes one; each is listed and revoked on its own. A release declares the developer's own apps from `.zitadel/apps/<slug>.json`, and only a release changes them. `zitadel apps create <slug> --preset <preset>` writes that file from one of eight presets, or registers the app through the API with `--registered`; `zitadel apps list` and `apps get` read them, and `@zitadel/config/app` exports the presets. Clients that register themselves through dynamic client registration (RFC 7591) are stored per project under a `dcr_` client_id, with the name, logo and links they claim, and join the app whose API their first authorization request names; one nobody consented to expires an hour after it registered. `POST /client_registrations/query`, `GET /client_registrations/{id}` and `zitadel client-registrations list` and `get` show them, and `DELETE /client_registrations/{id}` or `zitadel client-registrations delete` removes one with the consents users gave it.
