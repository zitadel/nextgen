Signing in after a protected route sent you to the login page now takes you back to that route. The middleware of `@zitadel/sdk-next`, `@zitadel/sdk-nuxt` and the other server SDKs sends a signed-out visit to `/login?next=<path>`, and `<zitadel-login>` now returns to that path after sign-in instead of always going to its `post-sign-in-url`, which pages generated by `zitadel setup` set to `/profile`. Only a path on the login page's own origin is followed: a `next` that is a full URL, starts with `//`, or contains a backslash or a control character is ignored, and the widget goes to `post-sign-in-url` as before. Pages that use `next` for something of their own can keep the old behavior with `force-post-sign-in-url` on the element, or `forcePostSignInUrl` on every SDK's `ZitadelLogin`.
