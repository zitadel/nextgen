# ADR 025: Default brand font loading

> **Status:** Accepted — 2026-06-15 (revised 2026-06-16: dropped APK Futural; headings use bold Arimo)

## Context

`<zitadel-login>` renders into a shadow root whose `--zl-font-family-*` tokens
name the brand face. The only code path that actually *loads* a face was
`applyFontUrl()` in `font-loader.ts`, which injects a document-level
`<link rel="stylesheet">` — and only when the flow response carries
`branding.font_url`.

That left a gap depending on which backend the widget talks to:

- The **mock auth server** (`@zitadel/api-mock`) injects a default Arimo
  `font_url` on every flow response, so `apps/demo-next` and `apps/demo-nuxt`
  paint Arimo.
- The **real Go server** returns a stub branding
  (`internal/api/branding.go` → `defaultBranding()`: `layout` +
  `liquid_template` only, "MVP fallback until the Branding API ships"). It has
  no `font_url`.

So an app generated by the CLI (`zitadel setup`, which runs against the real
local runtime) rendered the auth UI in the system fallback (Arial / system-ui),
never in the brand face. The font tokens named the brand face first, but nothing
loaded it.

A design-system default font is a property of the **components package**, the
same place that already ships the default `--zl-*` token *values*
(`applyBaseTokens`). `@font-face` rules declared inside a shadow root are ignored
by browsers, so any font the widget loads must be injected at **document** level.
`applyFontUrl` already does this; the default must too.

### Why not APK Futural for headings

Figma shows headings in **APK Futural**, a commercial face licensed from APK
Type. Its EULA (`V1-24`) makes shipping it impossible: the licence is
**non-transferable** and **may not be transferred to any third party**, and a
**Web Licence covers one web domain** only. `@zitadel/components` is MIT on
**public npm** and the server ships as a **public Docker image** — bundling the
woff2 (or even hard-coding a URL to it as the default) would hand a licensed
face to unlicensed third parties on their own domains. APK Futural is a
Zitadel-brand face for Zitadel's own surfaces, not a default for a white-label
component, so it is not referenced anywhere in this repo. Headings use **bold
Arimo** instead.

## Decision

`@zitadel/components` ships **Arimo** as the default brand face, loaded by the
orchestrator independently of branding. Headings use the same family rendered
**bold**. Tenant branding overrides the face.

1. `font-loader.ts` exports `applyDefaultFont(shadowRoot, href?)` alongside the
   existing `applyFontUrl`. Both share one document-level `<link>` injector;
   each owns a distinct id (`zl-default-font-link` vs `zl-font-link`) so they
   never clobber each other. Both stay idempotent and remove their link when
   called with `null`.
2. The default href is the exported constant `DEFAULT_BRAND_FONT_HREF` — the
   Arimo stylesheet (the same URL the mock dev branding uses), which includes
   weight 700 so headings render bold.
3. The orchestrator's `willUpdate` calls `applyDefaultFont` **unless** a tenant
   `branding.font_url` is present, in which case it drops the default link and
   `applyFontUrl` takes over. The default and override never both fetch.
4. The `--zl-font-family-sans` and `--zl-font-family-heading` token stacks both
   lead with `"Arimo"` (system fallbacks at the tail). The heading is
   distinguished by weight (`font-weight: 700` on `.zl-card-title`), not by a
   separate family.

### Asset strategy: linked stylesheet, not bundled bytes

The default loads via a stylesheet URL rather than a self-hosted font file
inlined into the package, for now:

- A self-hosted face means shipping woff2 bytes either as a base64 data URL in
  the JS bundle (bloats `dist` loaded on every page) or as emitted assets the
  host bundler must serve (fragile across Next/Vite/webpack/Turbopack — the very
  coupling the runtime-injection pattern avoids).
- A linked stylesheet is a small, textual, reviewable change and matches the
  existing `applyFontUrl` mechanism exactly.

`DEFAULT_BRAND_FONT_HREF` is exported so a deployment that cannot make a
third-party request (privacy/GDPR, CSP, offline) can self-host the same face
and pass its own href to `applyDefaultFont`.

## Consequences

- **Brand font out of the box.** CLI-generated apps, the console, and any
  server that returns no `branding.font_url` now paint Arimo instead of the
  system fallback. Verified live in Chrome against `demo-next`: the `.zl-card-title`
  heading computes to `font-family: Arimo` and `font-weight: 700`, with the Arimo
  `<link>` injected at document level and `document.fonts.check('700 16px Arimo')`
  returning `true`. The `applyDefaultFont` default-path injection (used when no
  tenant `font_url` is present) is covered by `font-loader.spec.ts` and uses the
  identical document-level link mechanism.
- **Override preserved.** `branding.font_url` still wins; the default link is
  removed when a tenant font is present, so there is no redundant request and no
  font clash.
- **Consistent ownership.** Default *face loading* now lives in the same package
  as the default token *values*; the server's branding stays the
  customisation/override surface, consistent with `branding.yaml`.
- **Third-party request by default.** The shipped default fetches Arimo from
  Google Fonts, so the unbranded login page makes one cross-origin request and
  exposes the end-user's IP to the font CDN. Mitigations: it is overridable per
  deployment via `applyDefaultFont(href)` / `DEFAULT_BRAND_FONT_HREF`, and a
  tenant `font_url` replaces it entirely. **Follow-up:** self-host the default
  face inside the package (commit a latin-subset Arimo woff2, emit/inline it at
  build time, and point the default `@font-face` at it) so the out-of-the-box
  default needs no third-party request and works offline.
- **No CSP work needed here.** The CLI-generated app sets no Content-Security
  -Policy, so the linked stylesheet loads without a `font-src` allowance. A
  deployment that enforces CSP must allow its chosen font origin — orthogonal to
  this decision.
- **APK Futural deferred.** If Zitadel's own branded surface ever needs APK
  Futural, it belongs behind the (future) Branding API / a deployment-configured
  `font_url` served from Zitadel's licensed domain — never bundled into the OSS
  artifacts.
