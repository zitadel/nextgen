# Events catalog

Living authority for wide-event emission (ADR 048 / ADR 049).

Each mutating statement (or authenticated request completion / background job)
maps to one or more Path B `event_type` values (or Path A `request.api`).
OpenAPI `GET /events` returns a discriminated `Event` union on `event_type`
(per-type `allOf` wrappers with typed `payload`). Go payload structs live in
`internal/domain/event_payload.go`; OpenAPI type schemas are generated by
`api/cmd/gen_event_schemas` from those constants.

The same generator writes a webhook per event type
(`api/openapi/endpoints/events/webhooks/`): the request the event shipper sends
a webhook sink, which the spec root lists under `webhooks` and the docs give a
page each. A new event type needs a payload mapping and a webhook description in
the generator, and an entry in the root's `webhooks`; the generator fails until
it has all three. The Retired and Contracted sections below decide what a
webhook page says about whether the event is sent (a retired type's webhook is
deprecated), and a test keeps the generator's statuses in step with them.

**Naming:** dot-separated segments (`auth.factor.password.set`). Per-resource
types — no generic admin.config.pushed bucket.

**`user.*` versus `auth.*`:** `user.*` is the user as a record (created,
updated, deleted). A user's credentials and sign-ins are not: they live under
`auth.*` and `session.*`. Setting a password is `auth.factor.password.set`,
not a `user.*` event, and enrolling a passkey is
`auth.factor.passkey.enrolled`. A consumer syncing user records filters on
`user.*` without receiving sign-in or credential traffic; a security consumer
gets every credential change from `auth.factor.*`. A credential event names
its user in the payload's `user_id`.

**Compound transactions:** emit one Path B event per semantic mutation in the
same TX (shared `request_id`).

**PII:** deny-by-default. Secrets, challenges, and token values never appear.

## Payload rules

1. **Envelope owns identity** — `entity_type` / `entity_id` / `session_id` /
   `token_id` / `client_id` / `flow_id` / `request_id` / actor identify the
   subject. Do **not** put the primary entity id in `payload` again.
   Exceptions: join events (membership) or a **secondary** id (e.g. `user_id`
   on a factor event; `auth_attempt_id` on a check event).
2. **Create** — full **allowlisted snapshot** of fields the mutate API
   actually writes. Never passwords, passkey challenges, or user attribute
   **values** unless `x-audit`.
3. **Update** — **delta with new values**: only fields that changed, each set
   to the **new** value. Absent field = unchanged. Not `changed_keys[]` for
   admin resources. Not a full row dump.
4. **User attributes** — same on **create and update**: list attribute
   **keys** that were written; include **values only** for schema fields
   marked `x-audit`. Never credentials.
5. **Delete / simple state flip** — empty `{}` unless a **reason enum** is
   required (for example session delete or user deactivate — see Deferred).
6. **Auth / authz / checks** — refs + enums + allowlisted arrays; keep SIEM
   join keys on columns and/or secondary payload ids (see SIEM note below).
7. **Share payload schemas** when create and update use the **same property
   bag** (update just omits unchanged fields). Deletes use the empty payload
   file.

### Allowlisted fields per resource

| Resource | Allowlisted in payload | Intentionally omitted |
|----------|------------------------|------------------------|
| **Project** | `name`, `origins` (full array as stored) | Secrets, key material |
| **Origin** | `pattern`, `kind` | — |
| **Team** | `name` | — |
| **Flow definition** | `name`, `status`, `user_schema`, `purposes`, `audience` | Full `steps` graph |
| **Branding** | `layout`, `logo_url`, `font_url`, `hero_url` | `liquid_template` |
| **Policy** | `operation`, `revision_id`, `config` (the instance's settings) | — |
| **Schema** | `kind`, `object_type` | Schema document body |
| **IdP connection** | `slug`, `protocol`, `template`, `display_name`, `revision_id` | Connection document body, `client_secret` |
| **IdP identity link** | `connection_id`, `user_id` | Provider subject, claims, tokens |
| **User** | `schema_id`; `attribute_keys[]`; `attributes` map **only** for `x-audit` fields | Non-`x-audit` values; passwords / factors |
| **Token** | `scopes[]` | Token string / JWE |
| **Auth check** | `check_id`, `check_type`, `auth_attempt_id` | Challenge/proof JSON |
| **Auth factor** | `user_id`, `factor_id` | Hash, public key material, challenges |
| **Variable** | `kind` (the rest of the row key beside `entity_id`); `secret` on set | `name` (it is `entity_id`); the value, plain or as ciphertext |

`PATCH /projects/{id}` today only renames (`name`). Origins are set on
**create** and changed only through add/remove (`origin.added` /
`origin.removed`), never through `patchProject`. Create emits `name` and
`origins`; update emits `name` when renamed.

### SIEM join path

Event **columns** carry correlation: `request_id`, `session_id`, `flow_id`,
`client_id`, `token_id`, `actor_id`, `entity_id`.

Path A `request.api` may also carry observed requestor context on metadata
(`ip`, `user_agent`, `origin` under `client`). Join Path B mutations to that
snapshot via `request_id`. Exported events enable offline SIEM rules; they
are not inputs to the live risk evaluator
([bot-detection.md](../flowengine/bot-detection.md)).

- Auth attempt `entity_id` ↔ check payload `auth_attempt_id`.
- Session after handoff: `session_id` **column** (set via `EmitSpec.SessionID`;
  not duplicated in attempt payloads).
- Factors: `entity_id` / payload `factor_id` + shared `request_id` when
  co-committed.

## Path A

| Trigger | `event_type` | `category` | Payload |
|---------|--------------|------------|---------|
| HTTP handler completes and `project_id` is known | `request.api` | `request` | `operation_id`, `method`, `route_template`, `status`, `duration_ms` |

`occurred_at` is request **start** so a `request_id` group sorts
`request.api` first, then in-TX Path B mutations. `created_at` is flush time.
Login/flow HTTP and `POST /projects` emit when the handler stamps `project_id`
(actor/token empty). Path B copies `request_id` from the HTTP request even
without AuthGate. `createFlow` mints `flow_id` before `CreateAuthAttempt` so
Path B `auth.attempt.created` shares `flow_id` / `session_id` columns with
Path A `request.api`. Probes (`livez` / `readyz`) do not.

Path A buffer: flush on batch size **N≈100** or age **T≈1s**. Capacity **C**
(default 2000); drop only when full; never block the request.

storing the rehash of an outdated password hash on sign-in, which rewrites the
existing password row in place.

## Retired

Types with no live producer today. They stay in `domain.EventType` and the
events API so stored rows keep decoding. A type moves back to Path B when a
producer appears again. A retired type is removed once its rows have aged out
of retention ([ADR 049](../../adrs/049-events-api-retention-export.md)) on
every supported deployment; that removal is its own breaking change.

| `event_type` | Retired by | Return |
|--------------|------------|--------|
| `flowdef.updated` | [#530](https://github.com/zitadel/nextgen/issues/530): a flow definition is an immutable revision, a change publishes a new one | none planned |
| `flowdef.deleted` | [#530](https://github.com/zitadel/nextgen/issues/530): no delete endpoint | with retirement under releases ([#536](https://github.com/zitadel/nextgen/issues/536)) |

## Contracted

Types whose API contract is published before their producer lands. Each has
a `domain.EventType` constant and an events API schema, so clients can be
built against it, but nothing emits it yet. A type moves to Path B with its
producer. None today.
