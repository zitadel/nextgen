The SvelteKit SDK is a `handle` hook that proxies and verifies sessions on the server. The login and logout widgets come from the [Svelte SDK](/docs/sdks/svelte).

<Callout title="Generated setup" type="info">
  The CLI writes `src/hooks.server.ts`, `src/env.ts` and the auth pages, and writes the backend URL, the project secret, and the project id to `.env.local`. It needs SvelteKit 3.
</Callout>

    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Declare the hook's settings in `src/env.ts`, so SvelteKit serves them from the server-only `$app/env/private`: from `.env.local` in development and from the platform's environment in production. A missing one fails each request with an error naming it, and SvelteKit never bundles them for the browser:

    ```ts
    import { defineEnvVars } from "@sveltejs/kit/env";

    export const variables = defineEnvVars({
      ZITADEL_URL: {},
      ZITADEL_PROJECT_SECRET: {},
      ZITADEL_PROJECT_ID: {},
    });
    ```

    Create `src/hooks.server.ts` and pass them to the handle:

    ```ts
    import { ZITADEL_PROJECT_ID, ZITADEL_PROJECT_SECRET, ZITADEL_URL } from "$app/env/private";
    import { createNextgenHandle } from "@zitadel/sdk-sveltekit/server";

    export const handle = createNextgenHandle({
      url: ZITADEL_URL,
      projectSecret: ZITADEL_PROJECT_SECRET,
      projectId: ZITADEL_PROJECT_ID,
      protectedRoutes: ["/profile"],
      loginPath: "/login",
    });
    ```

    Render the widget on the client only. Its config (`project` and the rest) is set as element properties, which server-rendered markup cannot carry; `onMount` never runs during server rendering, so the widget is created in the browser with its config already in place:

    ```svelte
    <script lang="ts">
      import { onMount } from "svelte";
      import { ZitadelLogin, configureZitadel } from "@zitadel/sdk-svelte";

      const project = configureZitadel({ projectId: "<project id>", proxyPath: "/__nextgen" });

      let mounted = $state(false);
      onMount(() => {
        mounted = true;
      });
    </script>

    {#if mounted}
      <ZitadelLogin {project} purpose="login" postSignInUrl="/profile" />
    {/if}
    ```
  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>The hook proxies same-origin `/__nextgen/*` requests to the backend, attaching the project secret only to the session handoff.</Step>
  <Step>It verifies the session token and puts the result on `event.locals.nextgenAuth`; read it with `getAuth(event)` in a load function or endpoint.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login widget returns after sign-in.</Step>
</Steps>

## Verify

- Start the app with `npm run dev`. Setup already wrote the URL, the secret, and the project id to `.env.local`.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Log out and confirm `/profile` redirects to `/login`.
