The SvelteKit SDK (`@zitadel/sdk-sveltekit`) is a `handle` hook, the SvelteKit function that runs on every request. It proxies `/__nextgen/*` to Zitadel and verifies sessions on the server. The login and logout components come from the [Svelte SDK](/docs/sdks/svelte).

<Callout title="Generated setup" type="info">
  The CLI writes `src/hooks.server.ts` and the auth pages, declares the hook's settings in `src/env.ts` (adding them to the app's own file when it has one), and writes the backend URL, the project secret, and the project ID to `.env.local`. It needs SvelteKit 3.
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- SvelteKit 3 with Svelte 5.
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The URL, project ID and project secret. Setup writes them to `.env.local` as `ZITADEL_URL`, `ZITADEL_PROJECT_ID` and `ZITADEL_PROJECT_SECRET`, and the project ID again as `VITE_ZITADEL_PROJECT_ID`, the name a Vite app exposes to the browser.

  </Tab>
  <Tab>
    Declare the hook's settings in `src/env.ts`, so SvelteKit serves them from the server-only `$app/env/private`: from `.env.local` in development and from the platform's environment in production. A missing one fails each request with an error naming it, and SvelteKit never bundles them for the browser. If the app already has `src/env.ts`, add the three entries to its `defineEnvVars` call:

    ```ts
    import { defineEnvVars } from "@sveltejs/kit/env";

    export const variables = defineEnvVars({
      ZITADEL_URL: {},
      ZITADEL_PROJECT_SECRET: {},
      ZITADEL_PROJECT_ID: {},
    });
    ```

    Create `src/hooks.server.ts` and pass them to the handle:

    ```ts
    import { ZITADEL_PROJECT_ID, ZITADEL_PROJECT_SECRET, ZITADEL_URL } from "$app/env/private";
    import { createNextgenHandle } from "@zitadel/sdk-sveltekit/server";

    export const handle = createNextgenHandle({
      url: ZITADEL_URL,
      projectSecret: ZITADEL_PROJECT_SECRET,
      projectId: ZITADEL_PROJECT_ID,
      protectedRoutes: ["/profile"],
      loginPath: "/login",
    });
    ```

    Render the login component on the client only. Its config (`project` and the rest) is set as element properties, which server-rendered markup cannot carry; `onMount` never runs during server rendering, so the component is created in the browser with its config already in place:

    ```svelte
    <script lang="ts">
      import { onMount } from "svelte";
      import { ZitadelLogin, configureZitadel } from "@zitadel/sdk-svelte";

      const project = configureZitadel({ projectId: "<project id>", proxyPath: "/__nextgen" });

      let mounted = $state(false);
      onMount(() => {
        mounted = true;
      });
    </script>

    {#if mounted}
      <ZitadelLogin {project} purpose="login" postSignInUrl="/profile" />
    {/if}
    ```
  </Tab>
</Tabs>

## What the hook does on each request

<Steps>
  <Step>The hook proxies same-origin `/__nextgen/*` requests to the backend, attaching the project secret only to the session exchange, the call that turns a completed sign-in into a session.</Step>
  <Step>It verifies the session token and puts the result on `event.locals.nextgenAuth`; read it with `getAuth(event)` in a load function or endpoint.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login component returns after sign-in.</Step>
</Steps>

## Check that sign-in works

1. Run `npm run dev`. Setup already wrote the URL, the secret and the project ID to `.env.local`.
2. Open `/register` on the dev server, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register a user. A completed sign-in lands on `/profile`.
4. Confirm `/profile` shows the signed-in state.
5. Sign out and confirm `/profile` redirects to `/login`.
