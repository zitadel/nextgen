The Nuxt SDK registers server middleware and plugins so Nuxt pages can read Zitadel auth state.

<Callout title="Generated setup" type="info">
  The CLI edits the first matching `nuxt.config.{ts,mts,js,mjs}` and keeps the backend URL server-side while exposing only the project id publicly.
</Callout>

## Setup

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI adds pages, plugins, module config, environment files, and the SDK package. On the Nuxt 4 layout, pages and plugins go under `app/`.

    <Files>
      <File name="app/pages/login.vue" />
      <File name="app/pages/register.vue" />
      <File name="app/pages/profile.vue" />
      <File name="app/plugins/zitadel-components.client.ts" />
      <File name="app/plugins/auth.server.ts" />
      <File name="nuxt.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`. When setup created the app itself, it also writes `app/app.vue` and an `app/pages/index.vue` that redirects to `/login`.
  </Tab>
  <Tab>
    Register the SDK's Nuxt module and configure it under `nextgen`. The module adds the server middleware and the plugin that exposes auth state.

    ```ts
    export default defineNuxtConfig({
      modules: ["@zitadel/sdk-nuxt/module"],
      nextgen: {
        url: process.env.ZITADEL_URL ?? "http://localhost:8080",
        loginPath: "/login",
        protectedRoutes: ["/profile"],
      },
      runtimeConfig: {
        public: {
          zitadelProjectId: process.env.NUXT_PUBLIC_ZITADEL_PROJECT_ID,
        },
      },
      build: {
        transpile: ["@zitadel/api", "@zitadel/components", "@zitadel/design-tokens"],
      },
      vue: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith("zitadel-"),
        },
      },
    });
    ```

    Nuxt loads `.env`, not the `.env.local` that setup writes. Put `ZITADEL_URL` and `NUXT_PUBLIC_ZITADEL_PROJECT_ID` in `.env` and keep it out of git, or start the dev server with `nuxt dev --dotenv .env.local`. The module finds `ZITADEL_PROJECT_SECRET` in `.env.local` on its own. It reads the URL and the secret when `nuxt dev` or `nuxt build` runs. For a built server, set `NUXT_NEXTGEN_URL` and `NUXT_NEXTGEN_PROJECT_SECRET` in its runtime environment instead, and build without the secret, in the environment and in files: the module also reads `.env.local`, Nuxt reads `.env`, and whatever the build finds is written into `.output/`.

    Register the web components on the client only, in `app/plugins/zitadel-components.client.ts` (`plugins/` in a project without an `app/` directory):

    ```ts
    import "@zitadel/components";

    export default defineNuxtPlugin(() => {});
    ```
  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>Register Nitro middleware for same-origin `/__nextgen/*` proxying.</Step>
  <Step>Validate the session token and attach auth state to the request event.</Step>
  <Step>Copy the auth state into Nuxt state during server rendering, so pages read it with `useAuth()`.</Step>
</Steps>

## Verify

- Start the app. A config that setup generated already carries the URL and the project id; for a manual setup, provide the variables as the Manual tab describes.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Log out and confirm protected pages redirect to `/login`.
