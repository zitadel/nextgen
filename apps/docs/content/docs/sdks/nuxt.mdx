The Nuxt SDK (`@zitadel/sdk-nuxt`) is a Nuxt module. It registers Nitro server middleware and plugins, so Nuxt pages can read Zitadel auth state.

<Callout title="Generated setup" type="info">
  The CLI edits the first matching `nuxt.config.{ts,mts,js,mjs}` and writes the backend URL and the project ID to `.env.local`. The module keeps the URL on the server and gives the browser only the project ID and the proxy path.
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- Nuxt 4 or newer.
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The URL, project ID and project secret. Setup writes them to `.env.local` as `ZITADEL_URL`, `ZITADEL_PROJECT_ID`, `ZITADEL_PROJECT_SECRET` and `NUXT_PUBLIC_ZITADEL_PROJECT_ID`.

## Wire the SDK into your app

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI adds pages, module config, environment files, and the SDK package, and nothing else: the SDK loads the web components and exposes the auth state itself. On the Nuxt 4 layout, pages go under `app/`.

    <Files>
      <File name="app/pages/login.vue" />
      <File name="app/pages/register.vue" />
      <File name="app/pages/profile.vue" />
      <File name="nuxt.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`. When setup created the app itself, it also writes `app/app.vue` and an `app/pages/index.vue` that redirects to `/login`.
  </Tab>
  <Tab>
    Register the SDK's Nuxt module and configure it under `nextgen`. The module adds the server middleware, the plugin that exposes auth state, and the client plugin that loads the web components.

    ```ts
    export default defineNuxtConfig({
      modules: ["@zitadel/sdk-nuxt/module"],
      nextgen: {
        loginPath: "/login",
        protectedRoutes: ["/profile"],
      },
      build: {
        transpile: ["@zitadel/api", "@zitadel/components", "@zitadel/design-tokens"],
      },
      vue: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith("zitadel-"),
        },
      },
    });
    ```

    In `nuxt dev` the module reads `ZITADEL_URL`, `NUXT_PUBLIC_ZITADEL_PROJECT_ID`, and `ZITADEL_PROJECT_SECRET` from the environment, or from `.env.local` when the environment has none, so the `.env.local` that setup writes works even though Nuxt itself loads only `.env`. A `nextgen.url` or `runtimeConfig.public.zitadelProjectId` in the config wins over the variables. The backend URL and the project secret default to `ZITADEL_URL` and `ZITADEL_PROJECT_SECRET` from the server environment; set `nextgen.url` or the `NUXT_NEXTGEN_*` variables only to override. A built server reads `ZITADEL_URL` and `ZITADEL_PROJECT_SECRET` from its own runtime environment when it starts, and `NUXT_NEXTGEN_URL` and `NUXT_NEXTGEN_PROJECT_SECRET` take precedence over them. `nuxt build` never copies the URL or the secret into `.output/`, so one build runs against any backend and the secret exists only where the server runs; a built server does not read `.env.local`. The public project ID is still read when `nuxt build` runs, so set `NUXT_PUBLIC_ZITADEL_PROJECT_ID` in the runtime environment to change it per deployment.

    The module also loads the web components on the client and provides the business copy overlay as `useNuxtApp().$zitadelBusinessLocales`, so the app does not install or import `@zitadel/components`.
  </Tab>
</Tabs>

## What the middleware does on each request

<Steps>
  <Step>Register Nitro middleware for same-origin `/__nextgen/*` proxying.</Step>
  <Step>Validate the session token and attach auth state to the request event.</Step>
  <Step>Copy the auth state into Nuxt state during server rendering, so pages read it with `useAuth()`.</Step>
</Steps>

## Component events

The components are plain custom elements, so each event is a DOM `CustomEvent` that carries its payload in `detail`. Every SPA SDK exposes the same events and payloads as callbacks.

| Event | Fires when | Detail | Components |
| --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first one. | `{ step }` | Login |
| `zitadel-flow-input` | The visitor edits a field. | `{ name, value }` | Login |
| `zitadel-flow-complete` | The flow reaches a terminal step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login |
| `zitadel-flow-redirect` | The component hands the browser to an identity provider. Nobody is signed in yet. | `{ redirect_url, step }` | Login |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session |

```vue
<zitadel-login :project="project" post-sign-in-url="/admin" @zitadel-flow-complete="track" />
```

## Check that sign-in works

1. Run `npm run dev`. Setup already wrote the URL, the project ID and the secret to `.env.local`. For a manual setup, provide them as the Manual tab describes.
2. Open `/register` on the dev server, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register a user. A completed sign-in lands on `/profile`.
4. Confirm `/profile` shows the signed-in state.
5. Sign out and confirm protected pages redirect to `/login`.
