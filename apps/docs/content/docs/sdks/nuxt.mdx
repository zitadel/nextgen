The Nuxt SDK is a Nuxt module that adds Zitadel sign-in to a Nuxt app. It registers server middleware and plugins, so pages can read the auth state.

<Callout title="Generated setup" type="info">
  The CLI edits the first matching `nuxt.config.{ts,mts,js,mjs}` and writes the Zitadel URL and the project ID to `.env.local`. The module keeps the URL on the server and gives the browser only the project ID and the proxy path.
</Callout>

## Add the module

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI adds pages, module config, environment files and the SDK package, and nothing else. The SDK loads the web components and exposes the auth state itself. On the Nuxt 4 layout, pages go under `app/`.

    <Files>
      <File name="app/pages/login.vue" />
      <File name="app/pages/register.vue" />
      <File name="app/pages/profile.vue" />
      <File name="nuxt.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder. It adds entries to `.gitignore` and managed sections to `AGENTS.md` and `README.md`. When setup created the app itself, it also writes `app/app.vue` and an `app/pages/index.vue` that redirects to `/login`.
  </Tab>
  <Tab>
    Register the SDK's Nuxt module and configure it under `nextgen`. The module adds the server middleware, the plugin that exposes auth state, and the client plugin that loads the web components.

    ```ts
    export default defineNuxtConfig({
      modules: ["@zitadel/sdk-nuxt/module"],
      nextgen: {
        loginPath: "/login",
        protectedRoutes: ["/profile"],
      },
      build: {
        transpile: ["@zitadel/api", "@zitadel/components", "@zitadel/design-tokens"],
      },
      vue: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith("zitadel-"),
        },
      },
    });
    ```

    In `nuxt dev`, the module reads `ZITADEL_URL`, `NUXT_PUBLIC_ZITADEL_PROJECT_ID` and `ZITADEL_PROJECT_SECRET` from the environment. If the environment has none, it reads them from `.env.local`. So the `.env.local` that setup writes works, even though Nuxt itself loads only `.env`. A `nextgen.url` or `runtimeConfig.public.zitadelProjectId` in the config wins over the variables.

    The Zitadel URL and the project secret default to `ZITADEL_URL` and `ZITADEL_PROJECT_SECRET` from the server environment. Set `nextgen.url` or the `NUXT_NEXTGEN_*` variables only to override them.

    A built server reads `ZITADEL_URL` and `ZITADEL_PROJECT_SECRET` from its own runtime environment when it starts. `NUXT_NEXTGEN_URL` and `NUXT_NEXTGEN_PROJECT_SECRET` take precedence over them. A built server does not read `.env.local`. `nuxt build` never copies the URL or the secret into `.output/`, so one build runs against any Zitadel instance, and the secret exists only where the server runs.

    The public project ID is still read when `nuxt build` runs. To change it per deployment, set `NUXT_PUBLIC_ZITADEL_PROJECT_ID` in the runtime environment.

    The module also loads the web components on the client and provides the business copy overlay as `useNuxtApp().$zitadelBusinessLocales`, so the app does not install or import `@zitadel/components`.
  </Tab>
</Tabs>

## What the module does

<Steps>
  <Step>Register Nitro middleware that proxies same-origin `/__nextgen/*` requests.</Step>
  <Step>Validate the session token and attach auth state to the request event.</Step>
  <Step>Copy the auth state into Nuxt state during server rendering, so pages read it with `useAuth()`.</Step>
</Steps>

## Events

The login, logout and session components are plain custom elements. Each event is a DOM `CustomEvent` that carries its payload in `detail`. Every SPA SDK exposes the same events and payloads as callbacks.

| Event | Fires when | Detail | Used by |
| --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first. | `{ step }` | Login |
| `zitadel-flow-input` | The user edits a field. | `{ name, value }` | Login |
| `zitadel-flow-complete` | The flow reaches its final step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login |
| `zitadel-flow-redirect` | The login component sends the browser to an identity provider (IdP). Nobody is signed in yet. | `{ redirect_url, step }` | Login |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session |

```vue
<zitadel-login :project="project" post-sign-in-url="/admin" @zitadel-flow-complete="track" />
```

## Verify the setup

- Start the app. Setup already wrote the URL, the project ID and the secret to `.env.local`. For a manual setup, provide them as the Manual tab describes.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Sign out and confirm protected pages redirect to `/login`.
