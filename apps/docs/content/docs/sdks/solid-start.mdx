The SolidStart SDK (`@zitadel/sdk-solid-start`) is request middleware that runs on every request. It proxies `/__nextgen/*` to Zitadel and verifies sessions on the server. The login and logout components come from the [Solid SDK](/docs/sdks/solid).

<Callout title="Generated setup" type="info">
  The CLI targets SolidStart 2. It writes `src/middleware.ts`, registers it in `vite.config.ts`, and writes the backend URL, the project secret, and the project ID to `.env.local`.
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- SolidStart 2 (`@solidjs/start` `^2.0.0`) with `solid-js` `^1.8.0`.
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The URL, project ID and project secret. Setup writes them to `.env.local` as `ZITADEL_URL`, `ZITADEL_PROJECT_ID` and `ZITADEL_PROJECT_SECRET`, and the project ID again as `VITE_ZITADEL_PROJECT_ID`, the name a Vite app exposes to the browser.

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Create `src/middleware.ts`. SolidStart 2 registers this module's default export as h3 middleware, so wrap the config in its `createMiddleware`; a bare config object registers nothing.

    ```ts
    import { createMiddleware } from "@solidjs/start/middleware";
    import { createNextgenMiddleware } from "@zitadel/sdk-solid-start/server";

    export default createMiddleware(
      createNextgenMiddleware({
        protectedRoutes: ["/profile"],
        loginPath: "/login",
      }),
    );
    ```

    Register it in `vite.config.ts`:

    ```ts
    import { defineConfig } from "vite";
    import { solidStart } from "@solidjs/start/config";
    import { nitro } from "nitro/vite";

    export default defineConfig({
      plugins: [solidStart({ middleware: "./src/middleware.ts" }), nitro()],
    });
    ```

    Load the login component with `clientOnly`. It registers custom elements when imported, which throws during server rendering, so a top-level import in a route renders an empty page:

    ```tsx
    import { clientOnly } from "@solidjs/start";

    const ZitadelLogin = clientOnly(() =>
      import("@zitadel/sdk-solid").then((m) => ({ default: m.ZitadelLogin })),
    );

    export default function Login() {
      return (
        <ZitadelLogin
          projectId={import.meta.env.VITE_ZITADEL_PROJECT_ID}
          proxyPath="/__nextgen"
          purpose="login"
          postSignInUrl="/profile"
        />
      );
    }
    ```

</Tabs>

## What the middleware does on each request

<Steps>
  <Step>The middleware proxies same-origin `/__nextgen/*` requests to the backend, attaching the project secret only to the session exchange, the call that turns a completed sign-in into a session.</Step>
  <Step>It verifies the session token and puts the result on `event.locals.nextgenAuth`; read it with `getAuth(getRequestEvent()!)` in a server function.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login component returns after sign-in.</Step>
</Steps>

Nitro loads `.env` and `.env.local` into `process.env` in development, so the middleware finds `ZITADEL_URL`, `ZITADEL_PROJECT_SECRET`, and `ZITADEL_PROJECT_ID` there. Only `VITE_`-prefixed variables reach the browser.

## Check that sign-in works

1. Run `npm run dev`. Setup already wrote the URL, the secret and the project ID to `.env.local`.
2. Open `/register` on the dev server, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register a user. A completed sign-in lands on `/profile`.
4. Confirm `/profile` shows the signed-in state.
5. Sign out and confirm `/profile` redirects to `/login`.
