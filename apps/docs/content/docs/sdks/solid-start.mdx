The SolidStart SDK is request middleware that proxies Zitadel requests and verifies sessions on the server. The login and logout components come from the [Solid SDK](/docs/sdks/solid).

<Callout title="Generated setup" type="info">
  The CLI targets SolidStart 2. It writes `src/middleware.ts`, registers it in `vite.config.ts`, and writes the Zitadel URL, the project secret and the project ID to `.env.local`.
</Callout>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder. It adds entries to `.gitignore` and managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Create `src/middleware.ts`. SolidStart 2 registers this module's default export as h3 middleware. Wrap the config in its `createMiddleware`, because a bare config object registers nothing.

    ```ts
    import { createMiddleware } from "@solidjs/start/middleware";
    import { createNextgenMiddleware } from "@zitadel/sdk-solid-start/server";

    export default createMiddleware(
      createNextgenMiddleware({
        protectedRoutes: ["/profile"],
        loginPath: "/login",
      }),
    );
    ```

    Register it in `vite.config.ts`:

    ```ts
    import { defineConfig } from "vite";
    import { solidStart } from "@solidjs/start/config";
    import { nitro } from "nitro/vite";

    export default defineConfig({
      plugins: [solidStart({ middleware: "./src/middleware.ts" }), nitro()],
    });
    ```

    Load the login component with `clientOnly`. It registers custom elements when imported, which throws during server rendering. A top-level import in a route therefore renders an empty page:

    ```tsx
    import { clientOnly } from "@solidjs/start";

    const ZitadelLogin = clientOnly(() =>
      import("@zitadel/sdk-solid").then((m) => ({ default: m.ZitadelLogin })),
    );

    export default function Login() {
      return (
        <ZitadelLogin
          projectId={import.meta.env.VITE_ZITADEL_PROJECT_ID}
          proxyPath="/__nextgen"
          purpose="login"
          postSignInUrl="/profile"
        />
      );
    }
    ```
  </Tab>
</Tabs>

## What the middleware does

<Steps>
  <Step>The middleware proxies same-origin `/__nextgen/*` requests to Zitadel. It adds the project secret only to the session exchange, the call that turns a completed sign-in into a session.</Step>
  <Step>It verifies the session token and puts the result on `event.locals.nextgenAuth`; read it with `getAuth(getRequestEvent()!)` in a server function.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login component returns after sign-in.</Step>
</Steps>

Nitro loads `.env` and `.env.local` into `process.env` in development, so the middleware finds `ZITADEL_URL`, `ZITADEL_PROJECT_SECRET` and `ZITADEL_PROJECT_ID` there. Only `VITE_`-prefixed variables reach the browser.

## Verify the setup

- Start the app with `npm run dev`. Setup already wrote the URL, the secret and the project ID to `.env.local`.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Sign out and confirm `/profile` redirects to `/login`.
