The SolidStart SDK is request middleware that proxies and verifies sessions on the server. The login and logout widgets come from the [Solid SDK](/docs/sdks/solid).

<Callout title="Generated setup" type="info">
  The CLI targets SolidStart 2. It writes `src/middleware.ts`, registers it in `vite.config.ts`, and writes the backend URL, the project secret, and the project id to `.env.local`.
</Callout>

## Setup

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI adds the middleware, the routes, environment files, and both SDK packages, and points the `solidStart()` plugin in `vite.config.ts` at the middleware.

      <File name="src/routes/register.tsx" />
      <File name="src/routes/profile.tsx" />

      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Create `src/middleware.ts`. SolidStart 2 registers this module's default export as h3 middleware, so wrap the config in its `createMiddleware`; a bare config object registers nothing.

    ```ts
    import { createMiddleware } from "@solidjs/start/middleware";
    import { createNextgenMiddleware } from "@zitadel/sdk-solid-start/server";

    export default createMiddleware(
      createNextgenMiddleware({
        protectedRoutes: ["/profile"],
        loginPath: "/login",
      }),
    );
    ```

    Register it in `vite.config.ts`:

    ```ts
    import { defineConfig } from "vite";
    import { solidStart } from "@solidjs/start/config";
    import { nitro } from "nitro/vite";

    export default defineConfig({
      plugins: [solidStart({ middleware: "./src/middleware.ts" }), nitro()],
    });
    ```

    Load the widget with `clientOnly`. Importing `@zitadel/sdk-solid` in a route is safe during server rendering (the package ships a `solid` export condition that SolidStart compiles for the server), but the widget's `project` handle is set as an element property, which server-rendered markup cannot carry. `clientOnly` creates the widget in the browser with its config already in place:

    ```tsx
    import { clientOnly } from "@solidjs/start";

    const ZitadelLogin = clientOnly(() =>
      import("@zitadel/sdk-solid").then((m) => ({ default: m.ZitadelLogin })),
    );

    export default function Login() {
      return (
        <ZitadelLogin
          projectId={import.meta.env.VITE_ZITADEL_PROJECT_ID}
          proxyPath="/__nextgen"
          purpose="login"
          postSignInUrl="/profile"
        />
      );
    }
    ```

    `ZitadelLogin` takes the callbacks `onFlowStep`, `onFlowInput`, `onFlowComplete`, `onFlowRedirect` and `onFlowError`; `ZitadelLogout` and `ZitadelSession` take `onSignout`, `onSessionMissing` when there is no session as the widget loads (the session card then goes to its `postSignOutUrl`, unless that URL is the page it is on), and `onSessionError` when loading the session or signing out fails some other way. Each receives the event detail. The signed-in card for a profile page is `ZitadelSession`, loaded the same way (`m.ZitadelSession`).

  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>The middleware proxies same-origin `/__nextgen/*` requests to the backend, attaching the project secret only to the session handoff.</Step>
  <Step>It verifies the session token and puts the result on `event.locals.nextgenAuth`; read it with `getAuth(getRequestEvent()!)` in a server function.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`.</Step>
</Steps>

Nitro loads `.env` and `.env.local` into `process.env` in development, so the middleware finds `ZITADEL_URL` and `ZITADEL_PROJECT_SECRET` there. Only `VITE_`-prefixed variables reach the browser.

## Verify

- Start the app with `npm run dev`. Setup already wrote the URL, the secret, and the project id to `.env.local`.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Log out and confirm `/profile` redirects to `/login`.
