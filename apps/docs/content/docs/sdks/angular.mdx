The Angular SDK exposes standalone components that wrap the shared Zitadel auth UI.

<Callout title="Generated proxy" type="info">
  Angular uses a dev-server proxy config rather than Vite middleware. Production still needs a same-origin proxy for `/__nextgen/*`. See [SDK proxy](/docs/concepts/sdk-proxy).
</Callout>

## Setup

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI writes the root component, adds auth routes and a proxy config, wires `angular.json`, adds environment files, and installs the SDK.

    <Files>
      <File name="src/app/app.ts" />
      <File name="src/app/app.html" />
      <File name="src/app/app.routes.ts" />
      <File name="proxy.conf.cjs" />
      <File name="angular.json" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once and pass the handle to the standalone component:

    ```ts
    import { Component } from "@angular/core";
    import { ZitadelLoginComponent, configureZitadel } from "@zitadel/sdk-angular";

    const project = configureZitadel({ projectId: "proj_123", proxyPath: "/__nextgen" });

    @Component({
      standalone: true,
      imports: [ZitadelLoginComponent],
      template: `<zitadel-auth-login [project]="project" purpose="login" postSignInUrl="/" />`,
    })
    export class LoginPage {
      project = project;
    }
    ```

    `configureZitadel` is the shared one from `@zitadel/api/config`, re-exported here with `getApi` and `getZitadelConfig`, so the components also pick up its global handle when no `[project]` is bound. `<zitadel-auth-login>` emits `flowStep`, `flowInput`, `flowComplete`, `flowRedirect` and `flowError`; `<zitadel-auth-logout>` and `<zitadel-auth-session>` (the signed-in card) emit `signout` and `sessionMissing`. Each payload is the event detail. When the visitor has no session, the session widgets fire `zitadel-session-missing` instead and render nothing; the session card also goes to its `postSignOutUrl` when one is set, unless that URL is the page it is on. An unset or cleared input leaves the widget on its default. Projected content goes into the element's light DOM, so `<zitadel-auth-logout>` accepts a `<template>` for a custom sign-out control; mark it `ngNonBindable` so Angular leaves its `{{display}}` placeholders to the element.
  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>The Angular wrapper renders the underlying custom element.</Step>
  <Step>The generated dev proxy forwards `/__nextgen/*` and adds the project secret to the session exchange, and to no other call.</Step>
  <Step>In production, you supply the same-origin proxy yourself. The generated app sends no credential, so that proxy must add the project secret to the session exchange, and to no other call. A plain rewrite cannot do that (see [SDK proxy](/docs/concepts/sdk-proxy#spas-in-production)).</Step>
</Steps>

## Verify

- Run `npm run dev`. Setup adds a `dev` script (`ng serve`) if your `package.json` has none.
- Register or sign in through the widget.
- Confirm sign-out works from the session card the generated profile renders (`zitadel-auth-session`).
- Remember that the wrapper selectors are `zitadel-auth-login`, `zitadel-auth-session`, and `zitadel-auth-logout`; the underlying custom elements are `zitadel-login`, `zitadel-session`, and `zitadel-logout`.
