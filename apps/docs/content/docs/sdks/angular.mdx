The Angular SDK (`@zitadel/sdk-angular`) is the single-page-app wrapper for the shared Zitadel login and logout components, exposed as standalone components. It provides the `zitadel-auth-login`, `zitadel-auth-logout` and `zitadel-auth-session` tags.

<Callout title="SPA proxy requirement" type="warn">
  An Angular single-page app has no server of its own. In development, the CLI writes a dev-server proxy config (`proxy.conf.cjs`) instead of Vite middleware. Production needs a same-origin proxy for `/__nextgen/*` that adds the project secret to the session exchange, and to no other call. The session exchange is the call that turns a completed sign-in into a session. See [SPAs in production](/docs/sdks/proxy#spas-in-production).
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- Angular 17 or newer. To create a new Angular app, use a Node version the Angular CLI accepts ([Node versions](/docs/get-started/quickstart#node-versions)).
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The project ID, the project secret and the server URL. Setup writes them to `.env.local` as `ZITADEL_PROJECT_ID`, `ZITADEL_PROJECT_SECRET` and `ZITADEL_URL`. The dev proxy stops with an error when `ZITADEL_URL` or `ZITADEL_PROJECT_SECRET` is missing.

    import { ZitadelLoginComponent, configureZitadel } from "@zitadel/sdk-angular";

    @Component({
      standalone: true,

      project = project;
    }

## Props and events

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` take the props below, spelled the same in every SPA SDK. An unset prop keeps the component's own default.

| Prop | Type | Default | Components | Description |
| --- | --- | --- | --- | --- |
| `project` | `ZitadelProject` | unset | Login, Logout, Session | The handle that `configureZitadel` returns. Wins over `projectId` and `proxyPath`. |
| `projectId` | `string` | unset | Login, Logout, Session | The project ID. Read when you pass no `project` handle. |
| `proxyPath` | `string` | `"/__nextgen"` | Login, Logout, Session | The same-origin path the component calls. |
| `purpose` | `CreateFlowBodyPurpose` | `"login"` | Login | The purpose of the flow. |
| `flowName` | `string` | unset | Login | Runs the flow definition with this `name`. Unset runs the project's default flow for the `purpose`. |
| `postSignInUrl` | `string` | unset | Login | Where to navigate after a completed sign-in. If the page's `next` query parameter names a path on the same origin, the component goes there instead. The server SDKs' middleware sets `next` when a signed-out visitor requests a protected route. |
| `forcePostSignInUrl` | `boolean` | `false` | Login | Navigates to `postSignInUrl` even when `next` names a path. Use it on a page that uses `next` for something of its own. |
| `postSignOutUrl` | `string` | unset | Logout, Session | Where to navigate after sign-out. |
| `resumeFlowId` | `string` or `null` | unset | Login | The ID of an existing flow to resume instead of starting a new one. Unset, `null` or `""` falls back to the `flow` query parameter. An ID that no longer resolves starts a new flow. |
| `variant` | `"widget"` or `"page"` | `"widget"` | Login, Session | `widget` is content-sized and paints no page chrome. `page` claims the viewport, paints the surface background and loads the brand font. On Login, `page` also focuses the first field. |
| `theme` | `"light"`, `"dark"` or `"auto"` | unset | Login, Logout, Session | The colour mode. Unset on Login follows the project's branding theme, then the variant default: `dark` for `page`, `auto` for `widget`. Logout defaults to `auto`. `auto` follows `prefers-color-scheme`. |
| `suppressHeader` | `boolean` | `false` | Login, Session | Hides the component's own heading block visually but keeps it in the accessibility tree. Use it on pages that already carry the heading. |
| `suppressPasswordToggle` | `boolean` | `false` | Login | Hides the show/hide button on password fields. |
| `heading` | `string` | `"Signed in as"` | Session | Overrides the heading text. |
| `logoutLabel` | `string` | `"Sign out"` | Session | Overrides the label of the sign-out action. |
| `locales` | `Record<string, Partial<Record<string, string>>>` | unset | Login | Copy overrides, merged over the built-in dictionaries and keyed by primary language subtag. For example, `{ en: { "identifier.title": "Welcome back" } }`. |
| `lang` | `string` | browser language | Login | A BCP-47 language override. |

Each component event reaches the callback in the last column. The callback receives the event's `detail` payload.

| Event | Fires when | Detail | Components | Callback |
| --- | --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first one. | `{ step }` | Login | `(flowStep)` |
| `zitadel-flow-input` | The visitor edits a field. | `{ name, value }` | Login | `(flowInput)` |
| `zitadel-flow-complete` | The flow reaches a terminal step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login | `(flowComplete)` |
| `zitadel-flow-redirect` | The component hands the browser to an identity provider. Nobody is signed in yet. | `{ redirect_url, step }` | Login | `(flowRedirect)` |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login | `(flowError)` |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session | `(signout)` |

`handoff_token` is the short-lived credential that a completed flow returns. The proxy exchanges it for a session.

```html
<zitadel-auth-login [project]="project" theme="light" (flowComplete)="track($event)" />
```

## Standard HTML attributes

The Angular components are tags (`zitadel-auth-login`, `zitadel-auth-logout` and `zitadel-auth-session`), and a tag already carries the standard HTML attributes. Put `class`, `style`, `id`, `data-*` or `aria-*` on it, and Angular applies them to the tag, not to the underlying custom element inside it.

```html
<zitadel-auth-login [project]="project" class="login" data-testid="login" aria-label="Sign in" />
```

## How requests reach Zitadel

<Steps>
  <Step>The Angular wrapper renders the underlying custom element, which calls the configured proxy path on the same origin.</Step>
  <Step>In development, the generated dev-server proxy forwards `/__nextgen/*` to Zitadel and adds the project secret to the session exchange, and to no other call.</Step>
  <Step>In production, you supply the same-origin proxy yourself. The generated app sends no credential, and a plain rewrite cannot add the project secret ([SPAs in production](/docs/sdks/proxy#spas-in-production)).</Step>
</Steps>

## Build for production

Run the app through its npm scripts. `npm run build` runs `node zitadel-ng.cjs build`: the Angular CLI reads no environment into client code, so `zitadel-ng.cjs` reads `ZITADEL_PROJECT_ID` from the environment, then from `.env.local`, writes it into `src/app/zitadel-project.ts` and runs the build. It needs Node.js 20.12 or newer.

- A hosting preset or CI job that runs `ng build` must run `npm run build`, and set `ZITADEL_PROJECT_ID` in the environment where there is no `.env.local`.
- On a clean checkout, a plain `ng` command fails to compile, because `src/app/zitadel-project.ts` is missing. After an `npm run`, it reuses the ID that run wrote.
- On a machine with `.env.local`, `npm run build` puts that file's project ID into the bundle unless the environment sets another.

## Render on the server

If your app renders on the server, mount the component on the client only, after hydration. The `zitadel-auth-login` wrapper sets `projectId` and `proxyPath` as element properties, so adding them to the wrapper does not put them in server markup. Alternatively, use a raw `<zitadel-login>` element with `project-id` and `proxy-path` as attributes. A component that starts before its configuration arrives shows an error instead of the flow.

## Check that sign-in works

1. Run `npm run dev`. Setup adds a `dev` script (`node zitadel-ng.cjs serve`) if your `package.json` has none.
2. Open the dev server URL, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register at `/register`, or sign in at `/login`. A completed sign-in lands on `/profile`.
4. Sign out from the session card (`zitadel-auth-session`) that the generated profile renders. You return to `/login`.
5. If you target the elements in browser automation, note the wrapper selectors `zitadel-auth-login`, `zitadel-auth-session` and `zitadel-auth-logout`. The underlying custom elements are `zitadel-login`, `zitadel-session` and `zitadel-logout`.

If sign-in fails in development, run `npx @zitadel/cli@latest doctor`. `doctor --fix` repairs a dev proxy that an earlier setup wrote ([SDK proxy](/docs/sdks/proxy#spas-in-production)).
