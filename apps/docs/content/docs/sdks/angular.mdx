The Angular SDK (`@zitadel/sdk-angular`) wraps the shared Zitadel login and logout components for Angular single-page apps (SPAs).

<Callout title="SPA proxy requirement" type="warn">
  The components call `/__nextgen/*` on your app's own origin. The CLI sets up a dev-server proxy config (`proxy.conf.cjs`) for local development, not Vite middleware. In production, you supply a same-origin proxy. It must add the project secret to the session exchange, and to no other call, so a plain rewrite cannot do it. See [SPAs in production](/docs/sdks/proxy#spas-in-production).
</Callout>

## Add the login component

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI installs the SDK, writes the root component, adds auth routes and a proxy config, wires `angular.json` and adds environment files.

    <Files>
      <File name="src/app/app.ts" />
      <File name="src/app/app.html" />
      <File name="src/app/app.routes.ts" />
      <File name="proxy.conf.cjs" />
      <File name="angular.json" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder. It adds entries to `.gitignore` and managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once and pass the handle to the standalone component:

    ```ts
    import { Component } from "@angular/core";
    import { ZitadelLoginComponent, configureZitadel } from "@zitadel/sdk-angular";

    const project = configureZitadel({ projectId: "proj_123", proxyPath: "/__nextgen" });

    @Component({
      standalone: true,
      imports: [ZitadelLoginComponent],
      template: `<zitadel-auth-login [project]="project" purpose="login" postSignInUrl="/" />`,
    })
    export class LoginPage {
      project = project;
    }
    ```
  </Tab>
</Tabs>

## Props

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` take the props below. Every SPA SDK spells them the same. An unset prop keeps the component's default.

| Prop | Type | Default | Used by | Description |
| --- | --- | --- | --- | --- |
| `project` | `ZitadelProject` | unset | Login, Logout, Session | The handle that `configureZitadel()` returns. It takes precedence over `projectId` and `proxyPath`. |
| `projectId` | `string` | unset | Login, Logout, Session | The project ID. Read only when you pass no `project` handle. |
| `proxyPath` | `string` | `"/__nextgen"` | Login, Logout, Session | The same-origin path the component calls. |
| `purpose` | `CreateFlowBodyPurpose` | `"login"` | Login | The purpose of the sign-in flow. |
| `flowName` | `string` | unset | Login | Runs the flow definition with this `name`. Unset runs the project's default flow for the purpose. |
| `postSignInUrl` | `string` | unset | Login | Where to go after a completed sign-in. If the page's `next` query parameter holds a path on the same origin, the component goes there instead. The server SDKs' middleware sets `next` when a signed-out visitor opens a protected route. |
| `forcePostSignInUrl` | `boolean` | `false` | Login | Goes to `postSignInUrl` even when `next` holds a path. Use it when your page uses `next` for something else. |
| `postSignOutUrl` | `string` | unset | Logout, Session | Where to go after sign-out. |
| `resumeFlowId` | `string` or `null` | unset | Login | The ID of an existing flow to resume instead of starting a new one. Unset, `null` and `""` fall back to the `flow` query parameter. An ID that no longer resolves starts a new flow. |
| `variant` | `"widget"` or `"page"` | `"widget"` | Login, Session | `widget` sizes to its content and adds no page styling. `page` fills the viewport, paints the surface background and loads the brand font. On Login, `page` also focuses the first field. |
| `theme` | `"light"`, `"dark"` or `"auto"` | unset | Login, Logout, Session | The color mode. On Login, unset follows the project's branding theme, then the variant default (`dark` for `page`, `auto` for `widget`). On Logout, unset means `auto`. `auto` follows `prefers-color-scheme`. |
| `suppressHeader` | `boolean` | `false` | Login, Session | Hides the component's heading visually but keeps it in the accessibility tree. Use it when the page already has a heading. |
| `suppressPasswordToggle` | `boolean` | `false` | Login | Hides the show/hide button on password fields. |
| `heading` | `string` | `"Signed in as"` | Session | Overrides the heading text. |
| `logoutLabel` | `string` | `"Sign out"` | Session | Overrides the label of the sign-out action. |
| `locales` | `Record<string, Partial<Record<string, string>>>` | unset | Login | Text overrides merged over the built-in dictionaries, keyed by primary language subtag. For example: `{ en: { "identifier.title": "Welcome back" } }`. |
| `lang` | `string` | browser language | Login | A BCP-47 language tag that overrides the browser language. |

## Events

Each event reaches the callback in the last column. The callback receives the event's `detail` payload.

| Event | Fires when | Detail | Used by | Callback |
| --- | --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first. | `{ step }` | Login | `(flowStep)` |
| `zitadel-flow-input` | The user edits a field. | `{ name, value }` | Login | `(flowInput)` |
| `zitadel-flow-complete` | The flow reaches its final step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login | `(flowComplete)` |
| `zitadel-flow-redirect` | The login component sends the browser to an identity provider (IdP). Nobody is signed in yet. | `{ redirect_url, step }` | Login | `(flowRedirect)` |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login | `(flowError)` |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session | `(signout)` |

```html
<zitadel-auth-login [project]="project" theme="light" (flowComplete)="track($event)" />
```

## Standard HTML attributes

The Angular components are tags: `zitadel-auth-login`, `zitadel-auth-logout` and `zitadel-auth-session`. A tag already carries the standard HTML attributes. Put `class`, `style`, `id`, `data-*` or `aria-*` on it, and Angular applies them to the tag itself, not to the element inside it.

```html
<zitadel-auth-login [project]="project" class="login" data-testid="login" aria-label="Sign in" />
```

## Render on the server

If your app renders on the server, mount the component on the client only, after hydration. The `zitadel-auth-login` wrapper sets `projectId` and `proxyPath` as element properties, so they do not reach the server markup. Alternatively, use a raw `<zitadel-login>` element with `project-id` and `proxy-path` as attributes. A component that starts before its configuration arrives shows an error instead of the flow.

## Verify the setup

- Run `npm run dev`. If your `package.json` has no `dev` script, setup adds one (`ng serve`).
- Register or sign in through the login component.
- Confirm sign-out works from the session card that the generated profile renders (`zitadel-auth-session`).
- Note the selectors. The wrappers are `zitadel-auth-login`, `zitadel-auth-session` and `zitadel-auth-logout`. The underlying custom elements are `zitadel-login`, `zitadel-session` and `zitadel-logout`.
