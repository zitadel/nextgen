`@zitadel/api` is generated from the OpenAPI source under `api/openapi/`.

It exposes:

- generated endpoint functions
- generated models
- Zod schemas
- MSW helpers
- runtime helpers for base URL and auth

## Usage

The package has no root export; import from its subpaths:

- `@zitadel/api/client` — `createZitadelClient`, a typed client bound to a base URL and an optional bearer token.
- `@zitadel/api/config` — `configureZitadel` and `getApi`, the shared browser configuration the components read. Every SDK except Angular uses it; the Angular SDK has its own `configureZitadel`.
- `@zitadel/api/generated/model` — request and response types.
- `@zitadel/api/generated/endpoints/zitadelNextGen` — the endpoint functions behind the client, with `.zod` and `.msw` variants for the Zod schemas and MSW handlers. Call the endpoints through `createZitadelClient`: on their own they use one base URL and token for the whole process, and the client sets both before each call. The MSW handlers need the optional peers `msw` and `@faker-js/faker`.
- `@zitadel/api/runtime/fetch` — `ApiError` and `NetworkError`, which a call throws when the request fails.
- `@zitadel/api/runtime/paging` — `pages()`, the cursor walk behind the client's list methods, for a request the client does not make.
- `@zitadel/api/runtime/base-url` and `@zitadel/api/runtime/auth` — low-level settings, such as the base URL and the token the client sets for you.

Call the API from server-side code:

```ts
import { createZitadelClient } from "@zitadel/api/client";

const client = createZitadelClient({
  baseUrl: process.env.ZITADEL_URL ?? "http://localhost:8080",
  token: process.env.ZITADEL_PROJECT_SECRET!, // server-side only
});

const project = await client.getProject(process.env.ZITADEL_PROJECT_ID!);
```

### Lists

A paged list method returns one page and its `next_page_token`. Each one also carries `items()`, `pages()` and `all()`, which take the same arguments and follow the cursor for you:

```ts
for await (const deployment of client.listDeployments.items({ project_id })) {
  if (deployment.status === "live") break; // later pages are never fetched
}

const schemas = await client.listSchemas.all({ project_id, limit: 100 });
```

`items()` and `pages()` fetch the next page only when the loop reaches it, so a loop that stops early reads nothing more. `limit` sets the page size, and a `page_token` among the arguments is where the walk starts. To change what every call returns, each page included, pass `onResponse` or `onError` to `createZitadelClient`.

Every operation in the [API reference](/docs/reference/api) shows its call through this client, beside its request and response shapes. The method is named after the operation and takes its path parameters, its body, then its query parameters; an optional body comes after required query parameters.
