The Qwik SDK is the SPA wrapper for the shared Zitadel login and logout widgets.

<Callout title="Requires Qwik 2" type="info">
  `@zitadel/sdk-qwik` peers `@qwik.dev/core` (`^2.0.0-beta.45`), so your app must be on Qwik 2. A Qwik 1 (`@builder.io/qwik`) app is not supported — migrate it to `@qwik.dev/core` first.
</Callout>

<Callout title="SPA proxy requirement" type="warn">
  Vite-based Qwik SPAs do not have server middleware by default. The CLI configures a Vite dev proxy; production deployments need an equivalent same-origin proxy for `/__nextgen/*`. See [SDK proxy](/docs/concepts/sdk-proxy).
</Callout>

## Setup

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI configures the Vite proxy, writes app-level auth UI, adds environment files, and installs the SDK.

    <Files>
      <File name="src/app.tsx" />
      <File name="vite.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    In an existing app, the CLI edits the `vite.config.*` you already have. Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once, then render login and logout widgets:

    ```tsx
    import { component$ } from "@qwik.dev/core";
    import { ZitadelLogin, ZitadelLogout, configureZitadel } from "@zitadel/sdk-qwik";

    const project = configureZitadel({
      projectId: import.meta.env.VITE_ZITADEL_PROJECT_ID,
      proxyPath: "/__nextgen",
    });

    export const LoginPage = component$(() => {
      return <ZitadelLogin project={project} purpose="login" postSignInUrl="/" />;
    });

    export const ProfilePage = component$(() => {
      return <ZitadelLogout project={project} postSignOutUrl="/login" />;
    });
    ```

    `ZitadelLogin` takes the callbacks `onFlowStep$`, `onFlowInput$`, `onFlowComplete$`, `onFlowRedirect$` and `onFlowError$`; `ZitadelLogout` and `ZitadelSession` take `onSignout$` and `onSessionMissing$`. Each QRL receives the event detail. When the visitor has no session, the session widgets fire `zitadel-session-missing` instead and render nothing; the session card also goes to its `postSignOutUrl` when one is set, unless that URL is the page it is on. `ZitadelSession` is the signed-in card (`<ZitadelSession project={project} />`). An unset or cleared prop leaves the widget on its default, for example the "Signed in as" heading. Children go into the element's light DOM, so `ZitadelLogout` accepts a `<template>` for a custom sign-out control (write its `{{display}}` placeholders inside a string literal, `{"Sign out {{display}}"}`) and `ZitadelLogin` accepts `slot="attribution-trailing"` content.
  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>The widgets call the configured proxy path on the same origin.</Step>
  <Step>In local Vite development, the generated proxy forwards `/__nextgen/*` to Zitadel and adds the project secret to the session exchange, and to no other call.</Step>
  <Step>In production, you supply the same-origin proxy yourself. The generated app sends no credential, so that proxy must add the project secret to the session exchange, and to no other call. A plain rewrite cannot do that (see [SDK proxy](/docs/concepts/sdk-proxy#spas-in-production)).</Step>
</Steps>

## Verify

- Run the Vite app with generated environment variables.
- Register or sign in through the rendered widget.
- Confirm logout returns to the configured login path.
- In browser automation, use shadow-DOM-aware locators because the native inputs live inside shared web components.
