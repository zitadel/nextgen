The Qwik SDK (`@zitadel/sdk-qwik`) is the single-page-app wrapper for the shared Zitadel login and logout components. It exports `ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` as Qwik components.

<Callout title="Requires Qwik 2" type="warn">
  `@zitadel/sdk-qwik` declares `@qwik.dev/core` (`^2.0.0-beta.45`) as a peer dependency, so your app must use Qwik 2. A Qwik 1 app (`@builder.io/qwik`) is not supported. Migrate it to `@qwik.dev/core` first.
</Callout>

<Callout title="SPA proxy requirement" type="warn">
  A Qwik single-page app has no server of its own. In development, the CLI configures a Vite proxy for `/__nextgen/*`. Production needs a same-origin proxy for `/__nextgen/*` that adds the project secret to the session exchange, and to no other call. The session exchange is the call that turns a completed sign-in into a session. See [SPAs in production](/docs/sdks/proxy#spas-in-production).
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- Qwik 2 (`@qwik.dev/core` `^2.0.0-beta.45`), in an app built with Vite. A Qwik 1 app is not supported.
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The project ID and secret. Setup writes them to `.env.local` as `ZITADEL_PROJECT_ID` and `ZITADEL_PROJECT_SECRET`, and the project ID again as `VITE_ZITADEL_PROJECT_ID`, the name a Vite app exposes to the browser.

## Wire the SDK into your app

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI configures the Vite proxy, writes the app's root component (`src/app.tsx`) with the `/login`, `/register` and `/profile` pages, adds environment files, and installs the SDK.

    <Files>
      <File name="src/app.tsx" />
      <File name="vite.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    In an existing app, the CLI edits the `vite.config.*` you already have. Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once, then render the login and logout components. `VITE_ZITADEL_PROJECT_ID` is the project ID that setup wrote to `.env.local`:

    ```tsx
    import { component$ } from "@qwik.dev/core";
    import { ZitadelLogin, ZitadelLogout, configureZitadel } from "@zitadel/sdk-qwik";

    const project = configureZitadel({
      projectId: import.meta.env.VITE_ZITADEL_PROJECT_ID,
      proxyPath: "/__nextgen",
    });

    export const LoginPage = component$(() => {
      return <ZitadelLogin project={project} purpose="login" postSignInUrl="/" />;
    });

    export const ProfilePage = component$(() => {
      return <ZitadelLogout project={project} postSignOutUrl="/login" />;
    });
    ```
  </Tab>
</Tabs>

## Props and events

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` take the props below, spelled the same in every SPA SDK. An unset prop keeps the component's own default.

| Prop | Type | Default | Components | Description |
| --- | --- | --- | --- | --- |
| `project` | `ZitadelProject` | unset | Login, Logout, Session | The handle that `configureZitadel` returns. Wins over `projectId` and `proxyPath`. |
| `projectId` | `string` | unset | Login, Logout, Session | The project ID. Read when you pass no `project` handle. |
| `proxyPath` | `string` | `"/__nextgen"` | Login, Logout, Session | The same-origin path the component calls. |
| `purpose` | `CreateFlowBodyPurpose` | `"login"` | Login | The purpose of the flow. |
| `flowName` | `string` | unset | Login | Runs the flow definition with this `name`. Unset runs the project's default flow for the `purpose`. |
| `postSignInUrl` | `string` | unset | Login | Where to navigate after a completed sign-in. If the page's `next` query parameter names a path on the same origin, the component goes there instead. The server SDKs' middleware sets `next` when a signed-out visitor requests a protected route. |
| `forcePostSignInUrl` | `boolean` | `false` | Login | Navigates to `postSignInUrl` even when `next` names a path. Use it on a page that uses `next` for something of its own. |
| `postSignOutUrl` | `string` | unset | Logout, Session | Where to navigate after sign-out. |
| `resumeFlowId` | `string` or `null` | unset | Login | The ID of an existing flow to resume instead of starting a new one. Unset, `null` or `""` falls back to the `flow` query parameter. An ID that no longer resolves starts a new flow. |
| `variant` | `"widget"` or `"page"` | `"widget"` | Login, Session | `widget` is content-sized and paints no page chrome. `page` claims the viewport, paints the surface background and loads the brand font. On Login, `page` also focuses the first field. |
| `theme` | `"light"`, `"dark"` or `"auto"` | unset | Login, Logout, Session | The colour mode. Unset on Login follows the project's branding theme, then the variant default: `dark` for `page`, `auto` for `widget`. Logout defaults to `auto`. `auto` follows `prefers-color-scheme`. |
| `suppressHeader` | `boolean` | `false` | Login, Session | Hides the component's own heading block visually but keeps it in the accessibility tree. Use it on pages that already carry the heading. |
| `suppressPasswordToggle` | `boolean` | `false` | Login | Hides the show/hide button on password fields. |
| `heading` | `string` | `"Signed in as"` | Session | Overrides the heading text. |
| `logoutLabel` | `string` | `"Sign out"` | Session | Overrides the label of the sign-out action. |
| `locales` | `Record<string, Partial<Record<string, string>>>` | unset | Login | Copy overrides, merged over the built-in dictionaries and keyed by primary language subtag. For example, `{ en: { "identifier.title": "Welcome back" } }`. |
| `lang` | `string` | browser language | Login | A BCP-47 language override. |

Each component event reaches the callback in the last column. The callback receives the event's `detail` payload.

| Event | Fires when | Detail | Components | Callback |
| --- | --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first one. | `{ step }` | Login | `onFlowStep$` |
| `zitadel-flow-input` | The visitor edits a field. | `{ name, value }` | Login | `onFlowInput$` |
| `zitadel-flow-complete` | The flow reaches a terminal step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login | `onFlowComplete$` |
| `zitadel-flow-redirect` | The component hands the browser to an identity provider. Nobody is signed in yet. | `{ redirect_url, step }` | Login | `onFlowRedirect$` |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login | `onFlowError$` |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session | `onSignout$` |

`handoff_token` is the short-lived credential that a completed flow returns. The proxy exchanges it for a session.

```tsx
<ZitadelLogin project={project} theme="light" onFlowComplete$={(detail) => track(detail)} />
```

## Standard HTML attributes

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` also take the standard HTML attributes (`class`, `style`, `id`, `title`, `slot`, `hidden`, `role`, `tabIndex`, `data-*` and `aria-*`) and pass them to the component element. You can position, style and label a component without an extra wrapper element. Nothing else reaches the element, so any other prop is ignored.

```tsx
<ZitadelLogin project={project} class="login" data-testid="login" aria-label="Sign in" />
```

## How requests reach Zitadel

<Steps>
  <Step>The components call the configured proxy path on the same origin.</Step>
  <Step>In development, the generated Vite proxy forwards `/__nextgen/*` to Zitadel and adds the project secret to the session exchange, and to no other call.</Step>
  <Step>In production, you supply the same-origin proxy yourself. The generated app sends no credential, and a plain rewrite cannot add the project secret ([SPAs in production](/docs/sdks/proxy#spas-in-production)).</Step>
</Steps>

## Render on the server

If your app renders on the server, pass `projectId` and `proxyPath` to the `ZitadelLogin` wrapper as strings: it writes them as the `project-id` and `proxy-path` attributes. Use those hyphenated names only on a raw `<zitadel-login>` element. A component that starts before its configuration arrives shows an error instead of the flow.

`ZitadelLogout` and `ZitadelSession` do the same. The other string and boolean options are written as attributes too: `purpose`, `flowName`, `postSignInUrl`, `forcePostSignInUrl`, `resumeFlowId`, `postSignOutUrl`, `variant`, `theme`, `heading`, `logoutLabel`, `lang`, `suppressHeader` and `suppressPasswordToggle`. A `project` handle contributes its `projectId`, `proxyPath`, `url` and `publishableKey` as attributes. The rest of the handle, and `locales`, are set as element properties after hydration. So a component that needs `locales` still gets them only on the client.

## Check that sign-in works

1. Run `npm run dev`. The app reads the variables that setup wrote to `.env.local`.
2. Open the dev server URL, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register at `/register`, or sign in at `/login`. A completed sign-in lands on `/profile`, which shows the signed-in session card.
4. Sign out from the session card. You return to `/login`.
5. In browser automation, use shadow-DOM-aware locators, because the native inputs live inside shared web components.

If sign-in fails in development, run `npx @zitadel/cli@latest doctor`. `doctor --fix` repairs a dev proxy that an earlier setup wrote ([SDK proxy](/docs/sdks/proxy#spas-in-production)).
