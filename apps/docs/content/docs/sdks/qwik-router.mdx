The Qwik Router SDK is an `onRequest` plugin that proxies Zitadel requests and verifies sessions on the server. The login and logout components come from the [Qwik SDK](/docs/sdks/qwik).

<Callout title="Requires Qwik 2" type="warn">
  The SDK has peer dependencies on Qwik 2: `@qwik.dev/core` and `@qwik.dev/router` (Qwik Router, which Qwik 2 renamed from Qwik City). A Qwik 1 app (`@builder.io/qwik-city`) is not supported, because the login components need Qwik 2. Migrate the app to `@qwik.dev/*` first. The CLI scaffolds new apps on Qwik 2.
</Callout>

## Install the SDK

Install both packages as dev dependencies. Qwik bundles `devDependencies` into the server build. Its starter `vite.config.ts` refuses to start when a package is listed in both sections.

<Tabs groupId="package-manager" items={["pnpm", "npm", "yarn"]}>
  <Tab>
    ```sh
    pnpm add -D @zitadel/sdk-qwik-router@latest @zitadel/sdk-qwik@latest
    ```
  </Tab>
  <Tab>

  </Tab>
  <Tab>

## Add the plugin

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI adds the plugin, the routes, environment files and both SDK packages. It changes no config file, because Qwik Router picks up `plugin@*.ts` route files on its own.

    <Files>
      <File name="src/routes/plugin@nextgen.ts" />
      <File name="src/routes/index.tsx" />
      <File name="src/routes/login/index.tsx" />
      <File name="src/routes/register/index.tsx" />
      <File name="src/routes/profile/index.tsx" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    Every setup also writes `zitadel.json` and the `.zitadel/` folder. It adds entries to `.gitignore` and managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Create `src/routes/plugin@nextgen.ts`. The handler reads `ZITADEL_URL`, `ZITADEL_PROJECT_SECRET` and `ZITADEL_PROJECT_ID` on each request from the request event's `env`, which is where Vite loads `.env.local`:

    ```ts
    import { createNextgenOnRequest } from "@zitadel/sdk-qwik-router/server";

    export const onRequest = createNextgenOnRequest({
      protectedRoutes: ["/profile"],
      loginPath: "/login",
    });
    ```

    Render the login component from a route:

    ```tsx
    import { component$ } from "@qwik.dev/core";
    import { ZitadelLogin, configureZitadel } from "@zitadel/sdk-qwik";

    const project = configureZitadel({
      projectId: import.meta.env.PUBLIC_ZITADEL_PROJECT_ID ?? "",
      proxyPath: "/__nextgen",
    });

    export default component$(() => (
      <ZitadelLogin project={project} purpose="login" postSignInUrl="/profile" />
    ));
    ```
  </Tab>
</Tabs>

## What the plugin does

<Steps>
  <Step>The plugin proxies same-origin `/__nextgen/*` requests to Zitadel. It adds the project secret only to the session exchange, the call that turns a completed sign-in into a session.</Step>
  <Step>It verifies the session token and stores the result on the request's `sharedMap`; read it with `getAuth(ev)` in a `routeLoader$`, action, or endpoint.</Step>
  <Step>It redirects unauthenticated requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login component returns after sign-in. A route matches with or without a trailing slash, because Qwik Router serves `/profile/` by default.</Step>
</Steps>

## Verify the setup

- Start the app with `npm run dev`. Setup already wrote the URL, the secret and the project ID to `.env.local`.
- Visit `/login` and register a user.
- Confirm `/profile` shows signed-in state.
- Sign out and confirm `/profile` redirects to `/login`.
