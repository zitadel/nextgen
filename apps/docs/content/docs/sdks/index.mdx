The preview publishes framework SDKs, shared UI components and a generated API client. They ship together in one release. Pick an SDK by how your app renders. Server frameworks proxy and verify sessions in middleware. Single-page app (SPA) frameworks render the same login and logout components behind a same-origin proxy.

<Callout title="Start with the CLI" type="info">
  Run `npx @zitadel/cli@latest setup` to set up an app. It scaffolds the right package and proxy for your framework. Use these SDK pages to review generated files, customize routes or integrate manually.
</Callout>

## Server frameworks

Auth runs in framework middleware. It proxies `/__nextgen/*`, verifies the session and guards protected routes on the server.

## SPA frameworks

The same shared login and logout components, rendered in the browser. They need a same-origin proxy for `/__nextgen/*`. The CLI wires one for local development. Production deployments supply their own.

## Choosing an SDK

All packages ship on npm's `latest` tag in one release. Install the same version of all of them, for example `pnpm add @zitadel/sdk-next@latest`. Until 1.0.0, a minor version can break, and its release note marks it **Breaking:**.

| Framework | Package | Rendering | Same-origin `/__nextgen/*` proxy | CLI scaffolds |
| --------- | ------- | --------- | -------------------------------- | ------------- |
| Next.js | `@zitadel/sdk-next` | Server (App Router) | Built into the SDK middleware | routes + `proxy.ts` (or `middleware.ts`, by the Next version in `package.json`) |
| Nuxt | `@zitadel/sdk-nuxt` | Server (Nitro) | Nitro server middleware | pages + module config in `nuxt.config` |
| SvelteKit | `@zitadel/sdk-sveltekit` + `@zitadel/sdk-svelte` | Server (SSR) | `handle` server hook | `src/hooks.server.ts` + routes |
| SolidStart | `@zitadel/sdk-solid-start` + `@zitadel/sdk-solid` | Server (SSR) | SolidStart request middleware | `src/middleware.ts` registered in `vite.config.ts` + routes |
| Qwik Router | `@zitadel/sdk-qwik-router` + `@zitadel/sdk-qwik` | Server (SSR) | Root `onRequest` plugin | `src/routes/plugin@nextgen.ts` + routes |
| TanStack Start | `@zitadel/sdk-tanstack-start` | Server (SSR) | Global request middleware | `src/start.ts` + routes |
| React | `@zitadel/sdk-react` | SPA | Vite dev proxy / your deploy proxy | Vite proxy + auth UI |
| Vue | `@zitadel/sdk-vue` | SPA | Vite dev proxy / your deploy proxy | Vite proxy + auth UI |
| Angular | `@zitadel/sdk-angular` | SPA | dev-server proxy / your deploy proxy | proxy config + components |
| Solid | `@zitadel/sdk-solid` | SPA | Vite dev proxy / your deploy proxy | Vite proxy + auth UI |
| Svelte | `@zitadel/sdk-svelte` | SPA | Vite dev proxy / your deploy proxy | Vite proxy + auth UI |
| Qwik | `@zitadel/sdk-qwik` | SPA | Vite dev proxy / your deploy proxy | Vite proxy + auth UI |
| Components | `@zitadel/components` | Web components | n/a (wrapped by an SDK) | — |
| API client | `@zitadel/api` | n/a | n/a | — |

The same-origin proxy is the one concept shared by every SDK. See [SDK proxy](/docs/sdks/proxy) for why `/__nextgen/*` must be same-origin and which call carries the project secret.
