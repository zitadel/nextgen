`@zitadel/components` is the package of web components, built with Lit, that every framework SDK wraps. It includes the `<zitadel-login>` login component.

<Callout title="Framework SDKs wrap this package" type="info">
  Most applications should install the framework SDK first. Use this package directly when embedding the web components yourself.
</Callout>

## Components

- `<zitadel-login>`, the login component
- `<zitadel-session>`, the signed-in session card with sign-out
- `<zitadel-logout>`
- atoms such as fields, buttons, alerts, icons, pills, and page shells

### Login component

The example runs `<zitadel-login>` against a mock of the flow API in your browser, so nothing you type leaves the page. Sign in with any email address and password, or switch `purpose` to sign up. `previewState` (the `preview-state` attribute) holds the step in one state and submits nothing, as the console's branding screen does.

## How the login component works

<Steps>
  <Step>Configure the project once with a project ID and proxy path.</Step>
  <Step>Render the login component for sign-in or registration flows.</Step>
  <Step>The component calls the flow API, renders each step, manages focus and submits with native form semantics.</Step>
</Steps>

The components call the configured API base. In generated apps, that is usually the same-origin `/__nextgen` proxy path.

In browser automation, note that the native controls live inside shadow roots. Prefer Playwright-style locators that reach into the shadow DOM.

If your app renders on the server, either mount the login component on the client only, after hydration, or give a raw `<zitadel-login>` element `project-id` and `proxy-path` as attributes. A component that starts before its configuration arrives shows an error instead of the flow.
