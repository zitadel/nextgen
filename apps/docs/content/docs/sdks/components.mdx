`@zitadel/components` contains Lit web components and the `<zitadel-login>` orchestrator used by framework SDKs.

<Callout title="Framework SDKs wrap this package" type="info">
  Most applications should install the framework SDK first. Use this package directly when embedding the web components yourself.
</Callout>

## Components

- `<zitadel-login>`
- `<zitadel-session>`, the signed-in session card with sign-out
- `<zitadel-logout>`
- atoms such as fields, buttons, alerts, icons, pills, and page shells

### The login

The example runs `<zitadel-login>` against a mock of the flow API in your browser, so nothing you type leaves the page. Sign in with any email address and password, or switch `purpose` to sign up. `previewState`, the `preview-state` attribute, holds the step in one state and submits nothing, as the console's branding screen does.

## Runtime model

<Steps>
  <Step>Configure the project once with a project id and proxy path.</Step>
  <Step>Render the login orchestrator for login or registration flows.</Step>
  <Step>The component calls the flow API, renders each step, manages focus, and submits with native form semantics.</Step>
</Steps>

The components speak to the configured API base, usually the same-origin `/__nextgen` proxy path in generated apps.

For browser automation, remember that the native controls live inside shadow roots. Prefer Playwright-style shadow-DOM-aware locators when available.

If your app renders on the server, mount the widget on the client only, after hydration, or give a raw `<zitadel-login>` element `project-id` and `proxy-path` as attributes, because a widget that starts before its configuration arrives shows an error instead of the flow.
