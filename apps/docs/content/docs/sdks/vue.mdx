The Vue SDK is the SPA wrapper for the shared Zitadel login and logout widgets, built for Vue 3.

<Callout title="SPA proxy requirement" type="warn">
  The CLI sets up a Vite dev proxy. Production deployments need a same-origin proxy for `/__nextgen/*`. See [SDK proxy](/docs/concepts/sdk-proxy).
</Callout>

## Setup

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI writes the app entry, configures the Vite proxy, adds environment files, and installs the SDK.

    <Files>
      <File name="src/App.vue" />
      <File name="vite.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    In an existing app, the CLI edits the `vite.config.*` you already have. Every setup also writes `zitadel.json` and the `.zitadel/` folder, adds its entries to `.gitignore`, and adds managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once, then render the components:

    ```vue
    <script setup lang="ts">
    import { ZitadelLogin, ZitadelLogout, configureZitadel } from "@zitadel/sdk-vue";

    const project = configureZitadel({
      projectId: import.meta.env.VITE_ZITADEL_PROJECT_ID,
      proxyPath: "/__nextgen",
    });
    </script>

    <template>
      <ZitadelLogin :project="project" purpose="login" postSignInUrl="/" />
      <ZitadelLogout :project="project" postSignOutUrl="/login" />
    </template>
    ```

    `ZitadelLogin` also takes `resumeFlowId`, an existing flow to resume instead of starting a new one; unset, `null` or `""` falls back to the `flow` query parameter.
  </Tab>
</Tabs>

## Runtime model

<Steps>
  <Step>The Vue components call the same shared Zitadel web components as the other SPA SDKs.</Step>
  <Step>The generated Vite proxy forwards `/__nextgen/*` to the backend during local development and adds the project secret to the session exchange, and to no other call.</Step>
  <Step>In production, you supply the same-origin proxy yourself. The generated app sends no credential, so that proxy must add the project secret to the session exchange, and to no other call. A plain rewrite cannot do that (see [SDK proxy](/docs/concepts/sdk-proxy#spas-in-production)).</Step>
</Steps>

If your app renders on the server, mount the widget on the client only, after hydration, or pass `project-id` and `proxy-path` as strings, because a widget that starts before its configuration arrives shows an error instead of the flow.

## Verify

- Run the Vite app with generated environment variables.
- Register or sign in through the rendered widget.
- Confirm logout returns to the configured login path.
- In browser automation, use shadow-DOM-aware locators because the native inputs live inside shared web components.
