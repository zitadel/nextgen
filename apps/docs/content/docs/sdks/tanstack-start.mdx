The TanStack Start SDK (`@zitadel/sdk-tanstack-start`) is a global request middleware that runs on every request. It proxies `/__nextgen/*` to Zitadel and verifies sessions on the server. Its `/react` entry adds typed React wrappers for the login and logout components.

<Callout title="Generated setup" type="info">
  The CLI writes `src/start.ts`, the server entry TanStack Start loads on its own, and writes the backend URL, the project secret, and the project ID to `.env.local`.
</Callout>

## Prerequisites

- Node.js 24 or newer. Run `node --version` to check.
- TanStack Start 1 (`@tanstack/react-start` `>=1.168.10`) with React 18 or newer.
- A Zitadel project from `zitadel setup`. Start the local runtime with `npx @zitadel/cli@latest start`, then run `npx @zitadel/cli@latest setup --server local` in your app's directory. See the [Quickstart](/docs/get-started/quickstart#scaffold-the-app-with-sign-in), or [Add Zitadel to an existing app](/docs/get-started/existing-app).
- The URL, project ID and project secret. Setup writes them to `.env.local` as `ZITADEL_URL`, `ZITADEL_PROJECT_ID` and `ZITADEL_PROJECT_SECRET`, and the project ID again as `VITE_ZITADEL_PROJECT_ID`, the name a Vite app exposes to the browser.

  <Tab>
    Create `src/start.ts`. Having this file opts the app out of TanStack Start's automatic CSRF protection for server functions, so restore it and run it before auth:

    ```ts
    import { createCsrfMiddleware, createMiddleware, createStart } from "@tanstack/react-start";
    import { createNextgenRequestMiddleware } from "@zitadel/sdk-tanstack-start/server";

    const csrfMiddleware = createCsrfMiddleware({
      filter: (ctx) => ctx.handlerType === "serverFn",
    });

    const authMiddleware = createMiddleware({ type: "request" }).server(
      createNextgenRequestMiddleware({
        protectedRoutes: ["/profile"],
        loginPath: "/login",
      }),
    );

    export const startInstance = createStart(() => ({
      requestMiddleware: [csrfMiddleware, authMiddleware],
    }));
    ```

    `protectedRoutes` only guards document requests. A client-side `<Link>` never reaches the request middleware, so guard the route itself in `beforeLoad` by calling a server function. A route's own `beforeLoad` context does not carry the session; a server function's does.

    ```tsx
    import { createFileRoute, redirect } from "@tanstack/react-router";
    import { createServerFn } from "@tanstack/react-start";
    import { getAuth } from "@zitadel/sdk-tanstack-start/server";

    // A server function's return value reaches the browser, so return only
    // client-safe fields: `getAuth` also carries the raw session token.
    const fetchAuth = createServerFn().handler(({ context }) => {
      const auth = getAuth(context);
      return auth.isAuthenticated
        ? { isAuthenticated: true as const, userId: auth.session.userId }
        : { isAuthenticated: false as const };
    });

    export const Route = createFileRoute("/profile")({
      beforeLoad: async () => {
        const auth = await fetchAuth();
        if (!auth.isAuthenticated) {
          throw redirect({ to: "/login" });
        }
      },
    });
    ```

    Never return `getAuth(context)` itself from a server function: its `session` carries the raw session token, and a server function's result reaches browser scripts. Return only `userId` and other client-safe fields.

    Render the components from `@zitadel/sdk-tanstack-start/react`. They mount client-only: on the server and during hydration they render nothing, so no flow starts before the app hydrates with its config. The `/react` entry also exports `businessLocales` and the Login, Logout and Session prop types; `@zitadel/sdk-tanstack-start/client` exports only `configureZitadel`, `getApi` and `getZitadelConfig`, with no element classes.

    ```tsx
    import { createFileRoute } from "@tanstack/react-router";
    import { configureZitadel } from "@zitadel/sdk-tanstack-start/client";
    import { ZitadelSession } from "@zitadel/sdk-tanstack-start/react";

    const project = configureZitadel({
      projectId: import.meta.env.VITE_ZITADEL_PROJECT_ID,
      proxyPath: "/__nextgen",
    });

    export const Route = createFileRoute("/profile")({
      component: () => <ZitadelSession project={project} postSignOutUrl="/login" />,
    });
    ```

    `ZitadelLogin` takes the callbacks `onFlowStep`, `onFlowInput`, `onFlowComplete`, `onFlowRedirect` and `onFlowError`; `ZitadelLogout` and `ZitadelSession` take `onSignout`. Each receives the event detail. The signed-in card for a profile page is `ZitadelSession`, as above.

## What the middleware does on each request

<Steps>
  <Step>The middleware proxies same-origin `/__nextgen/*` requests to the backend, attaching the project secret only to the session exchange, the call that turns a completed sign-in into a session.</Step>
  <Step>It verifies the session token and passes the result on as `nextgenAuth` in the request context, which server functions receive; read it with `getAuth(context)`.</Step>
  <Step>It redirects unauthenticated document requests for `protectedRoutes` to `loginPath`, with the requested path and query string in `?next=`, where the login component returns after sign-in. Routes guard client-side navigation in `beforeLoad`.</Step>
</Steps>

## Check that sign-in works

1. Run `npm run dev`. Setup already wrote the URL, the secret and the project ID to `.env.local`.
2. Open `/register` on the dev server, usually `http://localhost:3000/register`. Use the origin that setup registered: `localhost`, not `127.0.0.1`.
3. Register a user. A completed sign-in lands on `/profile`.
4. Confirm `/profile` shows the signed-in state.
5. Sign out and confirm `/profile` redirects to `/login`, both on a direct visit and from the landing page's link.
