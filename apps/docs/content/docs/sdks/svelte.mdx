The Svelte SDK (`@zitadel/sdk-svelte`) wraps the shared Zitadel login and logout components for Svelte 5 single-page apps (SPAs).

<Callout title="SPA proxy requirement" type="warn">
  The components call `/__nextgen/*` on your app's own origin, and Vite-based Svelte SPAs have no server middleware to answer. The CLI sets up a Vite dev proxy for local development. In production, you supply a same-origin proxy. See [SPAs in production](/docs/sdks/proxy#spas-in-production).
</Callout>

## Add the login component

<Tabs items={["CLI generated", "Manual"]}>
  <Tab>
    The CLI installs the SDK, configures the Vite proxy, writes the sign-in UI in your app and adds environment files.

    <Files>
      <File name="src/App.svelte" />
      <File name="vite.config.ts" />
      <File name=".env.local" />
      <File name=".env.example" />
      <File name="package.json" />
    </Files>

    In an existing app, the CLI edits the `vite.config.*` you already have. Every setup also writes `zitadel.json` and the `.zitadel/` folder. It adds entries to `.gitignore` and managed sections to `AGENTS.md` and `README.md`.
  </Tab>
  <Tab>
    Configure Zitadel once, then render the login and logout components:

    ```svelte
    <script lang="ts">
      import { ZitadelLogin, ZitadelLogout, configureZitadel } from "@zitadel/sdk-svelte";

      const project = configureZitadel({
        projectId: import.meta.env.VITE_ZITADEL_PROJECT_ID,
        proxyPath: "/__nextgen",
      });
    </script>

    <ZitadelLogin {project} purpose="login" postSignInUrl="/" />
    <ZitadelLogout {project} postSignOutUrl="/login" />
    ```
  </Tab>
</Tabs>

## Props

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` take the props below. Every SPA SDK spells them the same. An unset prop keeps the component's default.

| Prop | Type | Default | Used by | Description |
| --- | --- | --- | --- | --- |
| `project` | `ZitadelProject` | unset | Login, Logout, Session | The handle that `configureZitadel()` returns. It takes precedence over `projectId` and `proxyPath`. |
| `projectId` | `string` | unset | Login, Logout, Session | The project ID. Read only when you pass no `project` handle. |
| `proxyPath` | `string` | `"/__nextgen"` | Login, Logout, Session | The same-origin path the component calls. |
| `purpose` | `CreateFlowBodyPurpose` | `"login"` | Login | The purpose of the sign-in flow. |
| `flowName` | `string` | unset | Login | Runs the flow definition with this `name`. Unset runs the project's default flow for the purpose. |
| `postSignInUrl` | `string` | unset | Login | Where to go after a completed sign-in. If the page's `next` query parameter holds a path on the same origin, the component goes there instead. The server SDKs' middleware sets `next` when a signed-out visitor opens a protected route. |
| `forcePostSignInUrl` | `boolean` | `false` | Login | Goes to `postSignInUrl` even when `next` holds a path. Use it when your page uses `next` for something else. |
| `postSignOutUrl` | `string` | unset | Logout, Session | Where to go after sign-out. |
| `resumeFlowId` | `string` or `null` | unset | Login | The ID of an existing flow to resume instead of starting a new one. Unset, `null` and `""` fall back to the `flow` query parameter. An ID that no longer resolves starts a new flow. |
| `variant` | `"widget"` or `"page"` | `"widget"` | Login, Session | `widget` sizes to its content and adds no page styling. `page` fills the viewport, paints the surface background and loads the brand font. On Login, `page` also focuses the first field. |
| `theme` | `"light"`, `"dark"` or `"auto"` | unset | Login, Logout, Session | The color mode. On Login, unset follows the project's branding theme, then the variant default (`dark` for `page`, `auto` for `widget`). On Logout, unset means `auto`. `auto` follows `prefers-color-scheme`. |
| `suppressHeader` | `boolean` | `false` | Login, Session | Hides the component's heading visually but keeps it in the accessibility tree. Use it when the page already has a heading. |
| `suppressPasswordToggle` | `boolean` | `false` | Login | Hides the show/hide button on password fields. |
| `heading` | `string` | `"Signed in as"` | Session | Overrides the heading text. |
| `logoutLabel` | `string` | `"Sign out"` | Session | Overrides the label of the sign-out action. |
| `locales` | `Record<string, Partial<Record<string, string>>>` | unset | Login | Text overrides merged over the built-in dictionaries, keyed by primary language subtag. For example: `{ en: { "identifier.title": "Welcome back" } }`. |
| `lang` | `string` | browser language | Login | A BCP-47 language tag that overrides the browser language. |

## Events

Each event reaches the callback in the last column. The callback receives the event's `detail` payload.

| Event | Fires when | Detail | Used by | Callback |
| --- | --- | --- | --- | --- |
| `zitadel-flow-step` | Login shows a step, including the first. | `{ step }` | Login | `onFlowStep` |
| `zitadel-flow-input` | The user edits a field. | `{ name, value }` | Login | `onFlowInput` |
| `zitadel-flow-complete` | The flow reaches its final step. | `{ behavior, redirect_uri?, handoff_token?, handoff_token_expires_at? }` | Login | `onFlowComplete` |
| `zitadel-flow-redirect` | The login component sends the browser to an identity provider (IdP). Nobody is signed in yet. | `{ redirect_url, step }` | Login | `onFlowRedirect` |
| `zitadel-flow-error` | The flow reports an error. | `{ message }` | Login | `onFlowError` |
| `zitadel-signout` | The user signs out. | `{ display, identifier }` | Logout, Session | `onSignout` |

```svelte
<ZitadelLogin {project} theme="light" onFlowComplete={(detail) => track(detail)} />
```

## Standard HTML attributes

`ZitadelLogin`, `ZitadelLogout` and `ZitadelSession` also accept the standard HTML attributes: `class`, `style`, `id`, `title`, `slot`, `hidden`, `role`, `tabindex`, `data-*` and `aria-*`. They pass these to the underlying element, so you can position, style and label a component without a wrapper element. The element receives nothing else, and other props are ignored.

```svelte
<ZitadelLogin {project} class="login" data-testid="login" aria-label="Sign in" />
```

In Svelte, removing the `title` prop leaves `title="null"` on the element, because Svelte assigns it as a property.

## Render on the server

If your app renders on the server, either mount the component on the client only, after hydration, or pass `projectId` and `proxyPath` to the `ZitadelLogin` wrapper as strings. The wrapper writes them as the `project-id` and `proxy-path` attributes. Use those hyphenated names only on a raw `<zitadel-login>` element. A component that starts before its configuration arrives shows an error instead of the flow.

## Verify the setup

- Run the Vite app with the generated environment variables.
- Register or sign in through the rendered login component.
- Sign out and confirm you return to the configured login path.
- In browser automation, use locators that reach into the shadow DOM. The native inputs live inside shared web components.
