---
title: Project, team, and user
description: The three core resources, project, team, and user, and how a project is claimed.
---

Zitadel stores its data as projects, teams, and users. A project contains the other two.

## Project

A project is the top-level container and the data boundary. Every user, session, credential, team, audit event, and variable is stored in exactly one project, as is its configuration: schemas, flows, branding, identity providers, and releases. Data that must stay separate, such as a staging user base, belongs in a second project. Only access crosses projects: a user or team can hold a role on another project, and one team can own several projects.

## Team

A team is a group inside a project. Depending on the project, it can represent a paying customer or a B2B end-customer.

## User

A user is an identity inside a project. Depending on lifecycle policy, a user can be self-owned or team-owned.

## Claim

You create a project first and claim it later. Claiming attaches it to your team. A claimed project carries an active owning-team grant, the record that makes your team its owner.

Claim works end to end. The `zitadel claim` command, the OpenAPI endpoints, the server handlers, and the console claim page are all shipped. On the console claim page you sign in on the platform project and complete the claim in the browser.

A local project skips the browser step by default. `zitadel start` creates a local admin, `admin@zitadel.localhost`, with a team of its own. `zitadel setup --server local` attaches the new project to that team, so the local admin owns a local project as soon as setup finishes. `zitadel claim` then reports it as already owned. Use it as the fallback when that step failed.
