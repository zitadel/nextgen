---
title: Flows and schemas
description: The relationship between login flows, user schemas, and generated UI.
---

The flow engine drives login, registration, passkey, and related auth journeys.

A user schema defines **what** the platform stores about a user and how that user type can authenticate. A flow definition defines **when and where** users are asked to provide that data — which step renders when, and which fields each step collects. A flow names its schema by `objectType` in `user_schema` and runs against that schema's newest revision; its `steps[].fields` must name properties of it.

`zitadel setup` scaffolds editable copies of the default user schema and login flow into `.zitadel/schemas/` and `.zitadel/flows/`, uploads them, and seeds `.zitadel/state.json` so the local files and the platform start in sync. Each folder contains a README explaining what you can change.

The local files are the source of truth: edit them, then sync with `plan` and `apply` ([Edit the login flow and schema](/docs/guides/plan-apply)). An edit publishes a new immutable revision instead of changing the old one ([How syncing works](/docs/concepts/repo-config#how-syncing-works)).
