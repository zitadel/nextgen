---
title: Repo configuration
description: How Zitadel keeps app auth configuration reviewable.
---

Repo files describe configuration. Server APIs own runtime resources.

The CLI writes:

- `zitadel.json`
- `.zitadel/**`
- framework-specific app files
- environment files such as `.env.local`, and `.env.development.local` for the values the CLI reads

`zitadel deploy --dry-run` validates local configuration and shows the diff without mutating platform state.

`zitadel deploy` builds a release from repo configuration and deploys it to the project.

Local secrets and runtime-only state must stay out of source control. `.zitadel/local/**` is runtime data, not product configuration.
