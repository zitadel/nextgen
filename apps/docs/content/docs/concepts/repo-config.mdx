---
title: Repo configuration
description: How Zitadel keeps app auth configuration reviewable.
---

Repo files describe configuration. Server APIs own runtime resources.

The CLI writes:

- `zitadel.json`
- `.zitadel/**`
- framework-specific app files
- `.env.example`, the environment template to commit
- `.env.local`, with the project's real values, including the project secret

`zitadel plan` validates local configuration and previews the sync diff without mutating platform state.

`zitadel apply` validates and uploads repo configuration.

Local secrets and runtime-only state must stay out of source control: `.env.local`, `.zitadel/secret` (the project secret), and `.zitadel/local/**` (runtime data, not product configuration). Setup and `start` add them to `.gitignore`.
