These pages explain the model behind the preview: what each piece is and how the pieces fit together. They contain no steps; the guides do.

A [project](/docs/concepts/project-team-user) holds everything else: its users and teams, their sessions, and its configuration. That configuration lives in your repository as files ([Configuration as code](/docs/concepts/repo-config)) and reaches users as a [release deployed](/docs/concepts/releases-and-deployments) to the project's [origins](/docs/concepts/origins-and-previews). Above all, it holds the [user schemas and login flows](/docs/concepts/flows-and-schemas) that decide what a user is and how they sign in. A sign-in runs as an [authentication attempt](/docs/concepts/sessions-auth-attempts) and ends in a session. The server keeps all of it in one of the [databases](/docs/concepts/databases) it supports.
