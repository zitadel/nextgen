---
title: SDK proxy
description: Why framework SDKs proxy Zitadel requests through the app origin.
---

Framework SDKs keep auth traffic same-origin where possible.

For Next.js and Nuxt, the SDK middleware proxies `/__nextgen/*` requests to the Zitadel backend, validates the session token, and redirects unauthenticated users away from protected routes. A signed JWT is checked locally against the server's keys; the encrypted session tokens Zitadel issues today are checked against `GET /sessions/me`.

This keeps the app in control of browser-visible routes and cookies while Zitadel remains the backend API.

The default proxy path is:

```text
/__nextgen
```

The login and logout components call the same-origin proxy path by default when configured through the SDK.

## The project secret

One call in the browser flow needs a credential: `POST /sessions/exchange`, which turns a completed sign-in into a session. The proxy adds the project secret (`ZITADEL_PROJECT_SECRET`, which setup writes to `.env.local`) to that call as a bearer token, and to no other. The secret stays on the server side of the proxy and never reaches the browser.

## SPAs in production

Single-page apps (React, Vue, Angular, Solid, Svelte, Qwik) have no server of their own. In local development the CLI scaffolds a dev-server proxy for `/__nextgen/*` that adds the project secret to the session exchange. The CLI scaffolds nothing for production yet, and a plain rewrite cannot add the secret, so a production SPA needs a same-origin proxy of its own that does.

[ADR 036](https://github.com/zitadel/nextgen/blob/main/docs/adrs/036-api-credential-planes.md) will remove the project-secret requirement from this browser-facing path — a browser-safe, origin-checked credential replaces it, with the project's origin allowlist as the enforcement boundary. A plain platform entry will then be enough: a `vercel.json` rewrite, a `netlify.toml` redirect, or a minimal Cloudflare worker (Cloudflare redirects cannot proxy external origins), with no secrets in platform env stores. The credential rollout and CLI scaffolding for these platform configs are tracked in [zitadel/nextgen#560](https://github.com/zitadel/nextgen/issues/560).
