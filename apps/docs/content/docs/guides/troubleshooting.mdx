This page lists common CLI errors, what causes each, and how to fix it.

## Local runtime is not running

`console` reports `E_LOCAL_SERVER_NOT_RUNNING` when the local runtime is stopped. So do the commands that call Zitadel, such as `setup`, `deploy` or `variable`, when you run them with `--server local`.

Without the flag, those commands use the server the environment resolves (`ZITADEL_URL`). Against a stopped local runtime they fail with `E_NETWORK` (`ECONNREFUSED`).

In each case, start the local runtime again from the directory where you first ran `start`, the one with `.zitadel/local/`:

```sh
npx @zitadel/cli@latest start
```

Then retry the command. [Run Zitadel locally](/docs/guides/local-runtime) covers starting, stopping and resetting it.

## Port is in use

`start` or `doctor` reports `E_PORT_IN_USE` when another process already listens on the runtime's port.

If that process is a runtime the CLI started earlier with the default binary runtime, possibly in another directory, stop all of those (macOS and Linux only):

```sh
npx @zitadel/cli@latest stop --all
```

`stop --all` does not stop a Docker runtime. Run `stop` in the directory where you started that runtime.

Otherwise, stop the process that holds the port, or choose another port:

```sh
npx @zitadel/cli@latest start --port 8081
```

## JSON output looks mixed with installer logs

Capture stdout and stderr separately. The JSON envelope, the one JSON object a command prints, is on stdout. Package-manager progress belongs on stderr.

## Browser proof stops at the form

A rendered login or registration form does not prove that sign-in works. Complete registration, sign-out, sign-in and signed-in profile verification in a real browser.

## Old localhost passkeys still appear

Browser and operating system passkeys for `localhost` can outlive `zitadel reset --force`, deleted app folders and new local projects. If the passkey picker shows stale local accounts, remove the old `localhost` passkeys from your browser or operating system credential manager.

Password managers can also keep their save or update sheet open after the app redirects to the signed-in profile. An `Update Existing` prompt usually means the manager found an old `localhost` item with the same account label. Update it, save a new item, or delete the stale local passkey before you retry.
