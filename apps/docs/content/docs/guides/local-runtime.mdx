---
title: Run Zitadel locally
description: Start, stop and reset the local runtime the CLI manages, and sign in to its console.
---

`zitadel start` runs a Zitadel server on your machine for app development. This server is the local runtime.

```sh
npx @zitadel/cli@latest start
```

It runs the `@zitadel/server` npm binary that matches the CLI's version. The runtime is meant for app developers and agents. It needs no Docker, no Go and no checkout of this repository.

## What start creates

By default, `start` creates the platform project and a local admin, `admin@zitadel.localhost`. You own your local runtime from the start, without signing up. The admin's password is generated and kept in `.zitadel/local/admin.json`. It is never printed.

Projects that `zitadel setup --server local` creates are attached to the admin's team, so they are owned from the start ([Claim](/docs/concepts/project-team-user#claim)). Set `NEXTGEN_PLATFORM_BOOTSTRAP_PROJECT=false`, or pin another project, to start a bare runtime with neither.

The runtime keeps its state in the directory you started it in:

- `.zitadel/local/runtime.json`: the runtime's metadata, including its port.
- `.zitadel/local/nextgen-data`: its data. With no database override, that is SQLite at `zitadel.db` ([Databases](/docs/concepts/databases)).

None of it belongs in source control ([Configuration as code](/docs/concepts/repo-config#what-stays-out-of-source-control)).

## Open the console

`start` prints no console link, because its next step is `setup`. After `setup` has created your project, run `console`. It prints a one-time link that signs you in to the console as the local admin. Run earlier, the console only shows "No projects yet". The link works once, within a minute:

```sh
npx @zitadel/cli@latest console
```

The command opens the link in a browser. Add `--no-open` to print it without opening anything, which suits SSH and headless machines. It finds the local admin from the directory `start` ran in or one inside it. If it finds none, because `start` never ran there or ran with the platform bootstrap turned off, it fails with `E_VALIDATION` and tells you to run `start` first.

For how the CLI handles the credential file and the password, and how to turn the local admin off, see the [CLI skill](https://github.com/zitadel/nextgen/blob/main/apps/cli/skills/zitadel-cli/SKILL.md).

## Choose a port

Each directory runs its own local runtime. The first listens on `http://localhost:8080`. The next directory you start gets `8081`, and so on. A directory keeps its port when you stop and start it again. `start` prints the URLs and records the port in `.zitadel/local/runtime.json`. To choose a port yourself:

```sh
npx @zitadel/cli@latest start --port 8081
```

## Read the runtime's log

When a sign-in step or a request fails, the browser only says that it did. The runtime logs why, for example that it could not reach an identity provider. Keep the log open in another terminal while you work:

```sh
npx @zitadel/cli@latest logs --follow
```

On a terminal, warnings are yellow and errors red. To print only those:

```sh
npx @zitadel/cli@latest logs --level warn
```

`--level` takes `debug`, `info`, `warn` or `error`. `--tail` sets how many lines to print, 200 by default, counting only the lines `--level` shows. `logs` finds the runtime from the directory `start` ran in or one inside it.

## Check status, stop and reset

Run these in the directory `start` ran in. `setup`, `console`, `logs` and `doctor` also work from a directory inside it. `status`, `stop` and `reset` look for the local runtime only in the current directory, or in the one `--cwd` names.

Show status:

```sh
npx @zitadel/cli@latest status
```

Stop the runtime and keep its data:

```sh
npx @zitadel/cli@latest stop
```

Delete the runtime data:

```sh
npx @zitadel/cli@latest reset --force
```

`stop --all` is the exception. It stops every runtime the CLI started on this machine with the default binary runtime, wherever it ran (macOS and Linux only).

## Start the Docker runtime

The default runtime is the `@zitadel/server` binary. Use Docker only when you mean to test the Docker runtime:

```sh
npx @zitadel/cli@latest start --runtime docker
```
