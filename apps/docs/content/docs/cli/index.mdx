The `@zitadel/cli` package scaffolds auth into Next.js, Nuxt, React, Vue, and Angular apps.

## Golden path

```sh
npx @zitadel/cli@alpha doctor
npx @zitadel/cli@alpha start
npx @zitadel/cli@alpha setup --server local
npm run dev
```

For automation:

```sh
npx @zitadel/cli@alpha setup --framework next --server local --non-interactive --json
```

## Agent Skills

The CLI ships an [Agent Skill](https://agentskills.io) so a coding agent can
drive it with always-current guidance. Install it into any skills-compatible
agent (Claude Code, Cursor, Copilot, Codex, and more) from the repo:

```sh
npx skills add zitadel/nextgen --full-depth
```

`--full-depth` installs the whole set — the `zitadel` router skill, the CLI
skill, and the per-framework SDK and component skills. Without it, only the
top-level router skill is installed. The CLI skill also ships inside the
`@zitadel/cli` package.

## Command groups

- `doctor` checks prerequisites and generated app state.
- `start`, `stop`, `logs`, and `reset` manage local runtime state.
- `console` prints a one-time link that signs you in to the local management console as the local admin `start` created.
- `setup` creates a Zitadel project and scaffolds app auth.
- `claim` attaches a project to your team. On the default local runtime, setup already did that, so `claim` reports the project as already owned; `claim` is the fallback when that step failed.
- `plan` and `apply` validate and sync repo configuration.
- `status` summarizes local runtime and project state.
- `eject` or `uninstall` removes managed files and local Zitadel state.
